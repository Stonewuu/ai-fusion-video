# 完整剧本解析
忠实解析用户提供的原文，提取分集、场次、人物、场景和道具，不创作未提供的剧情。

## 完整执行要求
- 本任务的交付是授权范围内全部原文对应的已保存分集、场次、对白及资产关联。读完全文、保存概述和人物表、完成第一集或少量样例，都不等于完成解析。
- 不得因章节多、原文长、预计耗时长或认为“一次做不完”而主动收尾。工具可以跨多轮调用；一批完成后直接处理下一批，直到全部处理完或遇到真实阻塞。不要自行推测时间限制，也不要把尚可继续的工作转成“解析尚未完成”的最终回复。
- 维护原文范围清单：各章节/分集边界、已保存的实际分集 ID、场次解析结果、待处理范围。完成一集后更新清单；上下文整理或续跑时保留清单，再用查询回执核实，不只凭记忆判断进度。

## 执行步骤
1. get_project_script 获取剧本及 contentReads.rawContent。按其中版本与 nextOffset 用 read_script_content 连续读取，直到实际提供的内容完整；记录章节与已处理范围，跨段场次读完整后再处理。
2. list_project_assets 核对已有资产，query_asset_metadata 获取所需属性。覆盖原文所有实际地点，包括开场、过渡、车船内部与外部；反复使用的车辆、动物和器物列为道具。批量创建缺失主资产，不能只提取主要人物和大地点。
3. update_script_info 保存基于已读内容的概述、类型和人物表。名字统一，别名记在说明里，不能把两个不同人物仅因同名合并。
4. 按原文分集边界保存集记录。episodeNumber 是集号，scriptEpisodeId 是回执 ID；默认 sortOrder=episodeNumber。无分集边界时按用户意图组织，不能因标题提到总集数而补写缺少的原文。
5. 创建集按顺序使用剧本版本；确认保存后调用 episode_scene_writer，强类型传入实际 scriptEpisodeId。分集保存存在版本依赖，不并行创建；已保存且互不依赖的分集场次解析可分批并行，不要求在同一响应中塞入全部调用。子任务返回 partial 或 failed 时保留已保存成果，查明未完成范围和原因，不能把调用正常返回当作解析成功。
6. 每批完成后读取目标集的场次概要，核对是否覆盖该集原文，场景与人物关联是否成立。继续执行清单中的下一批；发现遗漏先补齐，不能连续查询同一份不完整结构后就结束。
save_script_episode 的 rawContent 保留原文；synopsis 才是概述。expectedVersion 在创建时用剧本 version，修改时用已读取分集的 version。已有内容不默认清空，重解析只覆盖用户明确选择的范围。

## 收尾检查
- 对照原文范围清单与 get_script_structure 的实际保存结果，逐项确认全部目标分集、各集场次与对白已经保存，人物、地点和道具关联齐全；未读范围、未保存分集和未完成子任务均为零，才可报告全量完成。不能仅凭总集数相等或子任务自述判定完成。
- 有剩余可执行工作时继续调用工具，不以文字总结结束。确有用户取消、授权不足、缺失必要信息或无法解决的工具故障时才停止，明确报告已保存范围、未完成范围及实际原因；不将局部成果标为全量成功，不清空或重复生成已核实完成的内容。
