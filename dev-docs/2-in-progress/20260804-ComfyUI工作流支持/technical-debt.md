# ComfyUI 对接待完成技术债务

## 使用规则

- 这里只记录当前版本无法完整解决、需要外部环境或后续版本处理的事项。
- 实施中发现的临时妥协必须立即登记；修复后保留记录并标记“已清偿”。
- 不允许用未登记的 fallback 掩盖缺失能力。

## 当前债务

### DEBT-COMFY-001：缺少真实 ComfyUI/GPU 联调环境

- 状态：待处理
- 原因：本地未部署 ComfyUI，用户说明后续另行通知测试。
- 当前可完成证据：官方协议实现、静态校验、单元测试、HTTP 契约测试。
- 后续验收：
  - 使用 ComfyUI v0.30.0 或用户实际版本完成连接检测。
  - 运行至少一个官方节点图片工作流。
  - 运行至少一个用户实际 custom node 视频工作流。
  - 验证上传、排队、取消、失败、输出下载、服务重启场景。

### DEBT-COMFY-002：ComfyUI Native API 未版本化

- 状态：接受并监控
- 风险：未来路由或字段可能发生变化。
- 当前策略：明确以 v0.30.0 为契约基线；连接检测只读取官方 `system.comfyui_version` 并探测 Jobs API，
  不做旧版字段或旧任务接口 fallback。
- 后续方向：按显式协议新增 `comfyui_v2`，不在 `comfyui` 内自动切换。

### DEBT-COMFY-003：第一版没有实时采样进度

- 状态：待后续版本
- 原因：现有 Task 只表达排队、处理中、完成、失败，第一版采用权威 HTTP 轮询。
- 后续方向：接入 `/ws`，增加远端进度快照与断线重连，不以 WebSocket 作为最终状态来源。

### DEBT-COMFY-004：自定义节点兼容性只能在目标实例验证

- 状态：待每个环境持续验证
- 风险：custom node 升级会修改 class_type、输入或输出结构。
- 当前策略：保存不可变工作流版本、required node 清单和验证结果；发布前必须在线验证。
- 后续方向：记录节点包及 commit/version 清单，支持环境差异报告。

### DEBT-COMFY-005：ComfyUI 任务历史与代理状态非持久化

- 状态：协议固有限制
- 风险：ComfyUI 重启后远端 job 可能无法恢复。
- 当前策略：平台预生成并持久化 prompt_id；结果完成后立即复制到平台存储；重启后查询不到任务时明确失败，不重复盲提。
- 后续方向：评估 Comfy API v2 的持久化实现或独立调度代理。

### DEBT-COMFY-006：实例级并发控制

- 状态：待后续版本
- 风险：现有并发按模型限制，多个模型可指向同一 GPU 实例。
- 当前策略：第一版依赖 ComfyUI 自身队列，并建议模型并发默认 1。
- 后续方向：增加以 `apiConfigId` 为键的分布式实例信号量；若本次实现可低风险完成则提前清偿。

### DEBT-COMFY-007：非图片上传能力的 Native API 差异

- 状态：当前版本已明确限制
- 风险：官方核心提供 `/upload/image`，参考视频/音频往往依赖节点或共享文件系统。
- 当前策略：图片输入作为第一等能力；执行器遇到 `uploaded_video` / `uploaded_audio` 绑定时直接拒绝，不探测私有上传接口，也不声明模型支持参考视频/音频上传。
- 后续方向：真实环境中验证目标 custom node 的上传/资产协议，再增加显式 transport 类型。

### DEBT-COMFY-008：取消与远端完成的竞态

- 状态：待后续强化
- 风险：用户取消与 ComfyUI 恰好完成可能同时发生；当前平台任务状态没有独立的 `cancelled` 枚举，只能用失败状态和“用户取消”消息表达。
- 当前策略：先取消远端 prompt，再更新本地 Item/Task；队列中的任务使用 Redis 精确移除，已完成任务不允许取消。
- 后续方向：为图片/视频 Task 增加独立取消状态，并用数据库条件更新保证“取消”和“完成”只有一个终态胜出。

### DEBT-COMFY-009：本地 MySQL 未启动，无法完成真实 Flyway validate

- 状态：受外部环境限制
- 当前证据：`FlywayMigrationNamingTests` 2/2 通过；含模型绑定、ComfyUI 单元/契约、输入/输出资源与图片/视频
  生成链路在内的后端选定验证集 46/46 通过。
- 阻塞表现：全量 `mvn test` 中 3 个 Spring 上下文测试类因 MySQL `Connection refused` 失败。
- 后续验收：启动项目目标 MySQL，执行应用启动或等价 Flyway validate，并重新运行全量测试。
