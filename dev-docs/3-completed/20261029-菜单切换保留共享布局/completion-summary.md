# 菜单切换保留共享布局

## 最终范围

已修正菜单导航导致整个工作区重新挂载的问题。顶部菜单切换时保留顶部栏，更新侧边菜单和内容；同一模块内切换侧边菜单时保留导航组件，只更新内容和选中状态。代码尚未发布。

## 原因与实现

根布局中的 ApplicationErrorBoundary 使用 `key={pathname}`，路径变化会让 React 丢弃其下整个组件树，包括 DashboardLayout、顶部栏、侧边栏和助手，并再次播放挂载动画。

ApplicationErrorBoundary 改为传入 `resetKey={pathname}`。ClientErrorBoundary 记录这个标识，在标识变化时清除旧错误，正常组件继续更新而不重新挂载。内容区的 OverlayScrollArea 仍以路径为 key，保留各页面独立的滚动生命周期。菜单导航仍使用原有客户端路由。

只修改两个错误边界组件，保留工作区原有的项目侧边菜单顺序调整；未修改基础 UI 组件、后端或数据库，也未增加依赖。

## 验证结果

- TypeScript 类型检查与两个修改文件的 ESLint 检查通过。
- 本地前端连接现有本地后端，在 Chrome 中验证仪表盘到工具、生图到生视频、工具到系统设置、通用设置到个人设置和浏览器返回。所有检查中浏览器文档与顶部栏节点保持不变，顶部栏没有动画样式变化；同一模块内侧边导航节点保持不变，内容区正常更新。
- 使用临时 React 验收页面验证 ClientErrorBoundary：正常子组件计数随 resetKey 变化保持不变；普通更新不清除错误；手动重试和切换 resetKey 均能恢复渲染。另确认页面错误入口能够返回仪表盘。验收路由已移除。
- 窄屏导航验收未完成：390px 宽度下助手收起后的浮层遮挡菜单。此次未调整该浮层，原因和影响范围仍待排查。
