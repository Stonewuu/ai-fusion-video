# 当前进度

已确认全局遮罩、弹窗本体和部分内部卡片同时使用 backdrop-filter。助手波纹持续播放时，即使没有操作弹窗，Chrome GPU 进程也接近满载。移除重复滤镜但保留波纹，仍有较高占用；暂停被遮住的波纹后，静置占用降至接近零。

最终只修改全局样式：整屏遮罩使用 2px 模糊和 1.25 倍饱和度；弹窗本体与内部卡片取消重复背景滤镜，保留原有半透明背景、边框和阴影。Dialog、Sheet 和自定义模态层存在期间暂停助手波纹，最后一个遮罩卸载后恢复；前景加载动画继续播放。

同一项目弹窗、1920×855 CSS 视口、DPR 2，采用 10 次往返滚动，每次 1250px、700px/s。8px 整屏模糊对照接近满载，2px 方案采样为 61%～82%，均值由约 95% 降至约 72%。最终代码静置采样六次均为零。无模糊对照连续滚动仍为 48%～59%，因此不能把剩余开销全部归因于毛玻璃。

已通过生产构建（含 TypeScript 检查）与变更文件空白检查。Chrome 中验证了浅色桌面表单、深色 390×844 窄屏表单的首项、中间项、末项、校验及禁用状态；验证嵌套弹窗、Select 菜单、Sheet、自定义模态层和前景加载动画。最后关闭项目测试弹窗，确认三个助手波纹恢复 running 状态。已清除诊断覆盖样式、恢复视口并停止隔离验证服务；本地前后端继续运行。
