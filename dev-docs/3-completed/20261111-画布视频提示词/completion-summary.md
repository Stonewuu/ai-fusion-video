# 画布视频提示词优化

已修复空 `videoPrompt` 导致镜头要求丢失、资产资料代替主提示词的问题，并更新本地后端。用户刷新画布后重新运行视频节点即可使用新输入；已完成任务的输入与生成结果保留原状。

## 实现

- 镜头的文本输出统一组织视频要求、画面内容、场景要求、对白与旁白、摄像、声音、转场和备注。已有内容参与同一次组合，不在缺少视频提示词时静默切换为另一套来源。生成时长仍由视频节点参数控制。
- 视频及输出视频的 ComfyUI 节点，将资产名称、描述、标签和结构化属性转成可读文本；移除资产生图要求、媒体地址和内部元数据。图片与文本生成继续使用原有资产输入。
- 上游连接的提示词为空时，已知输入在运行计划中报错，动态输入在解析阶段报错。模型支持的未连接提示词、仅媒体输入方式继续可用，显式媒体连接保持独立。
- 视频执行版本更新，重新预览和后续运行按新组合规则处理；旧任务快照没有回写。

## 验证

- `CanvasCreativeInputsTests`、`CanvasVideoPromptTests`、`CanvasAutomaticVideoTests` 共 22 项通过。新增用例保护缺少单独视频提示词时镜头内容仍进入 Google 请求、资产生图要求不干扰视频、连接空输入提前报错，以及已有非视频输入行为。
- 使用当天第一场镜头 1、第五场镜头 4 的持久化快照回放。前者的字幕、旁白、横移和雨声均保留；后者保留承认救人与劝退考生的动作及两句对白，输入由 2303 字缩减至 908 字。
- `git diff --check`、Maven 打包通过。Windows 下运行中的 JAR 占用构建目标，确认无执行中任务后停止旧后端并重新打包，再以隐藏后台进程启动。
- 本地启动完成，后端接口、前端代理接口和首页均返回 HTTP 200。未修改数据库迁移、未重新提交视频生成。

## 后续使用

需要按新提示词生成时，应从画布重新运行对应视频节点。历史任务详情继续展示原提交内容，本次没有替换历史视频，也未验证新视频的生成质量。
