# 兼容边界与维护约定

## 已处理

- 现有模型未声明 `videoRules` 时保留原参数规则；这用于兼容已有配置，不是请求失败时的回退。新契约版本未知或值无效须明确报错。
- `profile` 是文档与配置版本标识，不参与协议分派；`modelProtocol` 是唯一协议入口。只有三家真正相同的 content 数组结构共用构造器。
- 不修改任何 Flyway 脚本或生产历史；本次无新增数据库结构，执行快照继续使用既有持久化链路。
- Seedance 的 outputFormat、referenceTaskType，H3 Max 的 promptExpansionMode，Wan 的 promptExtend 是明确校验的模型覆盖项，会随配置冻结，不接受任意透传 JSON。

## 保留的产品边界

1. Seedance 草稿转成片、联网搜索、厂商素材库 asset ID，以及 Wan 的 file/link 需要各自完整的资源权限、过期处理、持久化与输入 UI；当前通用视频任务只暴露文本、首尾帧、图片/视频/音频参考，不宣称已支持这些额外流程，也不把它们塞入不受管理的扩展字段。
2. 托管素材可提前校验已知事实；外部 URL 的内容、视频编码/FPS、PNG 透明度等当前媒体事实模型不提供的信息由官方接口校验。不会为了预检隐式下载用户的外部 URL，也不会把未经探测的事实当作已验证。
3. MiniMax 官方 V2 文档存在矛盾：输入场景表列出单独尾帧，role 描述要求尾帧同时配首帧。当前预设采用成对首尾帧约束，单独尾帧需官方进一步确认后调整契约；不通过猜测放开。
4. MiniMax DELETE 同时有“取消排队任务”和“删除已结束任务”的语义，先查后删仍存在状态竞争。本接入不把该接口直接当作安全取消：沿用平台停止发布/追踪原任务的行为，不删除供应商记录，不重新提交。
5. 自动时长按模型最大输出时长预留额度；实际输出时长由结果与托管媒体探测确定。Wan usage.duration 包含输入时长，适配器只读取 output_video_duration。
6. 真实调用尚缺三家可用的官方配置及本轮费用上限。本地 HTTP 协议测试不能证明账户已开通、区域权限或实际模型服务可用。

## 后续变更入口

- 新型号：先更新预设 JSON 与官方来源记录，再扩展声明式约束；优先不用新增适配器。
- 新协议：新增独立策略与协议选择项；创建、查询、失败、取消边界必须有 HTTP 契约测试。
- 新规则字段：同时更新 Java 契约、TS 元数据、提交前校验、画布提示和能力工具；检查默认值、预算、快照、恢复记录，不只改请求构造。
- 单次生成特有新参数应增加正式任务字段与输入 UI；不能借用工作流字段、自由 JSON 或模型名称分支绕过校验和追踪。
