# 完成说明

自动整理在浏览器后台线程中加载 `elk.bundled.js` 时，库内部根据 `self` 环境进入独立 Worker 模式，没有提供合并入口预期的 Worker 构造器，导致 `_Worker is not a constructor`。页面将该异常显示为通用错误，保存接口尚未调用。此前仅在普通 Node 环境运行算法，未覆盖这个分支。

改用 `elk-api.js` 与独立 `elk-worker.ts` 入口，外层 Worker 继续执行候选比较、约束和连线路由，ELK Worker 执行分层算法，两者分别处理各自消息。引擎通过参数传给算法，任务结束后释放；后端仍只接收现有节点位置保存命令。

15 项相关回归、TypeScript、修改文件 ESLint 和前端生产构建通过。新增用例在独立线程的 `self` 环境中执行应用 Worker：旧代码复现原故障，新代码完成布局及路由，并正确返回循环约束错误。测试入口已加入 `test:canvas`。

Chrome 中当前 13 节点画布整理约 188 毫秒，保存成功，重复整理位置不变。验收的位置调整已撤销，保存后的节点坐标与验收前一致。临时诊断代码已通过重新加载页面清除，没有调用模型供应商接口。

本地前端已生效，原先打开的画布可刷新后重试。没有修改后端或数据库。
