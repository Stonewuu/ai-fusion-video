# 修复结果

已修复资产生图失败重试时移除参考图的缺口，并重新启动本地后端。问题与此前无限星河余额不足无关。

## 根因

资产执行任务 691ba007779e401bb6d502e0a997cb4c 使用用户原 DeepSeek 服务。图片任务 135 携带画风图和陆阳基础图，GPT Image 返回 HTTP 400 审核拒绝；随后智能体将托管媒体地址和本地画风图地址误判为可能不可用，在第二次 generate_image 调用中完全省略 imageUrls。任务 136 被当作独立纯文生图受理并写回资产。

后端原有参考图读取与转换逻辑未丢文件，但生图受理仅校验当前请求的模型能力，没有跨重试校验参考图；智能体提示词也允许无图降级，没有明确审核拒绝的处理边界。供应商没有说明具体是哪一项触发审核，不能归因于参考图或某个描述词。

## 最终改动

- 新增 AssetImageReferencePolicy，在 asset_image_executor 的图片受理事务中读取首次受理输入。省略、清空、部分移除、替换、增加或重排参考图都会返回 ASSET_IMAGE_REFERENCES_CHANGED，不创建任务或触发供应商请求。
- 复用现有运行行锁和持久化生成输入，允许提示词等内容调整，但固定参考图顺序与托管媒体版本；恢复执行和并发调用遵守同一约束。快照缺失时明确报错，不静默补默认值。
- 普通助手与工作台中的不同生图需求不受同一子资产任务约束影响，不新增数据库迁移。
- 工具向模型说明 media:// 和系统画风图由后端读取、转换；资产执行提示词要求审核、余额、额度或权限错误时停止，不自行移除参考图或调整请求绕过审核。基础形象识别同时覆盖本项目的 character、scene、prop 类型及受伤变体。

## 验证与交付

- 40 项相关单元测试通过，覆盖参考图参数变化、媒体版本、受理前拦截、媒体传输及持久化等待。
- 3 项独立 MySQL 集成测试通过，覆盖失败后的实例恢复、任务与用户作用域隔离、并发受理的运行行锁。测试使用 MyBatis-Plus 和现有 Mapper，没有直接写 JDBC 查询。
- 后端打包成功；本地 local 服务重新启动并完成 Flyway validate，前后端 HTTP 检查通过。没有用户提示词覆盖阻挡本次内置提示词更新。
- 未调用供应商重新生图，没有产生新的图片费用；既有任务 136 的图片内容保持原样。此修复防止后续重试丢失参考约束，不保证原请求能够通过供应商审核。
