# 智能体长消息恢复

1.4.0 将历史消息的推理和正文都改为 `LONGTEXT`。正文同时保存工具参数和结果。运行事件的 `payload_json` 也改为 `LONGTEXT`，供一次性返回完整结果的工具使用。

每次运行的待写事件队列默认可容纳 20,000,000 字节。工具等待事件也最多保存 20,000,000 字节，按 UTF-8 编码计算，包含 JSON 转义和事件字段。分段输出按顺序合并成历史消息。MySQL 的单包上限 `max_allowed_packet` 作用于整行读写，包括同一条消息里的推理和正文。

## 验证结果

- MySQL 8.0.46 上从 v1.3.1 的表结构升级。旧结构分别拒绝过长的推理和正文。升级后 Flyway 校验通过，已有中文、表情符号和空值均保留。
- MySQL 8.4.6 上从运行事件恢复各含 100 万个 Unicode 字符的推理、回复、工具参数和工具结果。按原文逐项比对通过，重复恢复后消息顺序和数量正确。
- 用 `o200k_base` 分词器确认一段文本含 100 万个 token，UTF-8 编码为 19,000,000 字节。在 64 MiB 的 MySQL 单包设置下，同一条回复的推理和正文各存入一份该文本，工具参数和结果也逐项读回一致。外部工具单次返回包含该文本的 JSON 后，会话历史可以读到完整结果。
- 使用本地模拟模型接口验证了流式回复和断线重连。重新连接后收到的文本与原回复一致，模型接口只收到一次请求。

## 升级

部署含此迁移的后端后，Flyway 在启动时升级表结构。对于仍保留运行事件、会话未删除且历史保存未完成的已结束运行，后台恢复任务会继续补写消息。
