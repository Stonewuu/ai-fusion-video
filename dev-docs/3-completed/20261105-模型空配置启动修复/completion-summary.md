# 模型空配置启动修复交付

## 问题与修复

模型的附加配置允许留空，但模型请求受理代码使用画布 JSON 解析器直接读取空字符串，导致任务在发出模型请求之前失败，并显示与画布有关的错误提示。本地失败记录的画布范围为空，也没有登记模型调用，确认错误来源是模型配置解析。

请求受理现在复用 AiModelRequestOptions 的解析规则：未设置、空字符串和空白均表示没有附加参数；非空内容必须是合法 JSON 对象。保留请求指定的思考等级，并继续核对运行身份、当前模型配置、并发额度和请求唯一性。没有通过修改用户配置为 `{}` 来绕过问题。

## 验证结果

- 修复前用回归测试复现相同的空配置启动错误。
- 24 项测试通过，无失败、错误或跳过，覆盖空配置、非法格式、思考等级覆盖、运行期间模型配置变化、任务启动与配置快照。
- 使用隔离 MySQL、Redis 和模拟模型，验证数据库中保存空字符串配置的模型可以完成剧本任务启动、请求受理、调用登记和任务结束，并且保存的配置仍为空字符串。
- 后端生产打包通过。本地后端已更新，35 条数据库迁移校验通过；18080 后端及 3000 前端代理的状态接口均返回 HTTP 200 和业务成功。

## 当前状态

修复位于 v-1.3.1，本地环境已经生效，未发布正式版本。用户可以重新发起原失败任务。测试没有调用用户配置的供应商接口，也没有重新解析用户的小说；用户模型配置和已有任务记录保留。
