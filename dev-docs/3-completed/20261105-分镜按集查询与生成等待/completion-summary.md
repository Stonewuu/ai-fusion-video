# 完成记录

在 v-1.3.1 完成分镜按集读取、默认排序、长文本预算以及普通媒体生成等待。

## 查询与顺序

`get_storyboard(storyboardId)` 只返回分集和场次的信息、版本与数量，不返回镜头正文，也不先加载镜头正文再删字段。镜头数量通过带有效资源过滤的 SQL 聚合取得。提供单个 `storyboardEpisodeId` 才返回该集镜头；拒绝跨分镜分集、多集数组和全量详情参数。场次详情继续使用现有工具。主调度器逐集读取并分发，前端目录卡片展示层级与数量，不把未查询的详情显示为空。

新增分镜集默认把集号写入已有 sortOrder，避免并行完成顺序影响排列，也避免为插入一集修改其他集的版本。明确指定位置和集合 REORDER 仍可手动排序，未改变已有用户数据。

## 文本与生成等待

读取预算随模型配置容量变化：单次最多为上下文配置的八分之一，最高 64000 字符；直接提供模型的工具结果阈值为读取预算两倍。未配置上下文时每段最多 8000 字符。超出时完整保存，保留用户与会话隔离、正文版本和 Unicode 续读位置。字符预算不是 token 精确计量，内核继续管理整个会话的压缩。

普通资产、分镜与画布生成使用同一持久化等待。提交回执给出等待工具，SUBMITTING 和排队不再作为失败重试依据。后台查询验证原用户、团队、项目和画布节点范围，任务完成后保存工具结果及恢复消息，再在恢复的执行中写回。未知或需要核实的状态原样报告，不伪造失败。前端区分已受理、处理中、完成、部分完成与待核实，并显示生成媒体。
