# 交付结果

拖动、松手和自动整理后均使用贝塞尔曲线。每次点击「自动整理」都会在浏览器重新计算。再次点击会取代尚在计算的布局，完成、位置未变和自动取消均不弹通知。整理期间改选节点或收到画布修改时会丢弃过时结果，只有坐标发生变化才保存。

画布上显示的连线决定节点的先后顺序。每个终点都要等所有可满足的起点排好后再进入下一层。路径有明确的延续方向时尽量对齐相连的端口，几条路径汇合时根据入线的位置安排终点。多个输入连接同一节点时按目标端口和输入序号排列。卡片尺寸、分组、锁定和选区决定可用空间。

在 13 节点项目关系画布的 Chrome 只读预览中，14 条已有连线均从左向右，曲线没有穿过卡片，重复整理的位置一致。打开两类项目关系线后，页面显示的 29 条连线全部参与整理。该预览没有提交画布编辑。回归测试还验证了节点类型和数据存储顺序改变时，只要连接、尺寸和端口相同，整理位置就一致。

服务端确认画布访问权限和同步起点后，立即发出不带事件序号的连接消息。Chrome 中空闲画布同步请求的首次响应从 15.3 秒缩短至 34–39 毫秒。使用 MySQL 和 Redis 的画布持久化测试及接口测试已通过，覆盖连接后的编辑、断点续读和权限撤销。
