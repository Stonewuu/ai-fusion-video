# 交付结果

拖动、松手和自动整理后均使用贝塞尔曲线。每次点击「自动整理」都会在浏览器重新计算。再次点击会取代尚在计算的布局，完成、位置未变和自动取消均不弹通知。整理期间改选节点或收到画布修改时会丢弃过时结果，只有坐标发生变化才保存。

连到同一生成节点的独立输入按目标端口和参考顺序排列。长短分支汇合时，中间节点会在前后连接点之间分配横向空间，并保留锁定、选区和分组约束。

在 13 节点项目关系画布上，「林夕 → 子资产 → 镜头」两段水平间距从 752、96 调整为 424、424 个画布单位。重复整理的位置一致。Chrome 中检查了已保存的 14 条关系连线，并在另一张画布上验证拖动过程中、松手及保存后均显示曲线。包含文本、两张参考图、视频和导出的五节点回归确认连线没有交叉或穿过卡片。

服务端确认画布访问权限和同步起点后，立即发出不带事件序号的连接消息。Chrome 中空闲画布同步请求的首次响应从 15.3 秒缩短至 34–39 毫秒。使用 MySQL 和 Redis 的画布持久化测试及接口测试已通过，覆盖连接后的编辑、断点续读和权限撤销。
