# 边界与风险

- MyBatis 类型处理器的 JDBC 方法签名属于框架序列化扩展；不允许业务代码借此执行 SQL 或管理连接。先检查能否直接使用框架自带类型处理器。
- 测试数据库的初始化、Flyway 校验和数据断言与生产业务访问区分；不能为减少扫描数字而削弱数据库集成验证。
- 重点保留 FOR UPDATE、SKIP LOCKED、条件版本更新、受影响行数判断、数据库 UTC 时间、逻辑删除和账号/团队过滤。不得把这些语义退化为先查后改。
- 当前工作区包含大量既有未提交改动；逐文件基于当前内容迁移，不重置工作区，不覆盖用户并行修改。

## 复查后的维护约束

- 有复合主键的表可以使用 BaseMapper 的 insert、条件 select/update/delete；不得将其中一个字段伪装为单列主键后调用 ById，也不为普通条件操作保留一套重复 SQL。
- 数据库时钟与应用时间不能互换；CURRENT_TIMESTAMP、UTC_TIMESTAMP 和表示绝对时刻的 Instant 各自保留原业务含义。类型处理使用框架内置能力，禁止重新引入 JDBC 包装层。时区行为依据 MySQL Connector/J 的日期时间处理与 MyBatis 内置类型处理器，并由现有资源集成用例验证。
- 媒体文件 I/O 不得持有数据库事务；此前迁移使用的长事务行锁已替换为 Spring Integration RedisLockRegistry，复用现有 Redis，使用独立续租线程和即时尝试获取。状态查询使用 BaseMapper，保留关系及清理任务租约在 READ_COMMITTED 短事务内重新核实；事务返回后再调用文件系统或对象存储。
- Redis 对象锁只负责跨实例互斥，不替代数据库中的权限、任务租约与执行代数。所有实例必须使用同一个 Redis 锁域；获取或完成时续租失败均不能报告成功，失效锁不得删除其他实例的新锁。Redis 故障时不回退到 JVM 本地锁或无锁执行。
- 锁域从数据库切换到 Redis 后，部署时不能混跑旧行锁工作者和新对象锁工作者；需要停止旧工作者后统一更新，避免两种锁互不相认。本地验收也按先停止旧后端、再启动新构建的顺序更新。
- Redis 租约不是存储端 fencing：进程长时间暂停、Redis 锁数据丢失时，已经发出的存储请求无法由 Redis 撤回。原有独立对象键、数据库代数和完成校验继续阻止旧结果发布；对象存储请求设有总超时，孤儿仍按保留期清理。不能宣称这把锁实现了数据库与对象存储的原子提交，也不能因此缩短保留期或移除代数校验。
- 文件 I/O 入口直接拒绝实际事务及事务同步作用域，不使用事务注解制造空同步作用域：NEVER 默认仍可能让 Spring 绑定并持有查询连接，NOT_SUPPORTED 也只是暂停外层事务，无法释放外层已持有的连接和行锁。新增或调整入口应覆盖慢 I/O、并发清理和旧执行者结束的场景。
