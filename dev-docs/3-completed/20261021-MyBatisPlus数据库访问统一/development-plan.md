# 数据库访问统一

## 目标

与三家官方视频模型接入一起完成现有业务 JDBC 迁移。普通增删改查使用 MyBatis-Plus；复杂查询、聚合、加锁和条件更新放入 Mapper XML。不得保留改名后的 JDBC 包装层。

## 实施顺序

2026-10-22 补充复查范围：媒体上传、来源导入、预览、画布导出和孤儿物理清理的完整 I/O 调用链。数据库只做短状态事务，文件操作使用跨实例对象互斥；验证慢 I/O 时连接释放、并发操作可继续、旧代数不得发布、清理领取失效时不得完成。不改 Flyway 迁移，也不通过暂停外层事务掩盖长连接占用。

1. 盘点实际调用、实体与 Mapper，保存本地源码快照并确认事务、权限和并发约束。
2. 先迁移生成任务与画布运行，再迁移资源、媒体、协作及其余调用；复用现有实体和 Mapper，必要时补充明确的实体或查询投影。
3. 将嵌入业务代码的复杂 SQL 移入 XML，以具名参数和业务方法表达查询，不开放任意 SQL 执行入口。
4. 调整受影响的现有测试依赖；保留状态、权限、幂等、锁与额度等业务断言，删除机械或重复用例，不以更换测试预期掩盖行为变化。
5. 使用独立测试数据库完成现有集成回归，检查代码格式、启动、Mapper 注册与迁移校验，再更新专用本地验收服务。

不修改已发布 Flyway 脚本，不改变本机主开发库的数据和历史。临时分析、截图、日志及脚本仅保存在 Git 忽略的 .local/verification 下。
