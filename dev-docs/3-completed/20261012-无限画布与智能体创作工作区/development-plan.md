# 无限画布与智能体创作工作区完整方案

立项日期：2026-10-12。完成日期：2026-10-24。状态：已完成。所属产品版本：1.3.0。1.2.0 已于 2026-10-11 正式发布，本次无限画布功能归入新版本；已发布迁移保持原样。最终范围与验证结果见同目录 completion-summary.md。

本方案已经完成 A–G 工作包，并纳入后续创作意图、节点编辑与快捷运行的调整。专业节点及其子任务执行已经提交的运行计划，交互助手仍遵循用户选择的审批模式；这一执行方式以已完成的“创作意图驱动的画布重构”为准。原先因 Agnes 队列失败而缺少的真实视频验收，已结合后续成功的真实视频调用和本次画布合成、提帧、导出验证补齐。音频和 ComfyUI 的真实外部服务仍按 2026-10-16 明确的范围调整免测。

将无限画布建设为平台完整的创作工作区：用户和智能体可以在同一画布中组织项目设定、编写与解析剧本、维护资产、编辑分镜、生成图片和视频、处理首尾帧、生成配乐与音效、合成与预览成片，并追踪每一次修改和运行。

核心架构采用 React Flow、Zustand 和现有 Spring Boot、MySQL、Redis、AgentScope。画布、普通业务页面与智能体共同调用受权限、版本和幂等约束的业务命令。剧本、分镜、资产继续由现有业务实体承载，画布负责空间组织、引用、执行计划和交互。

本文定义的是完整目标产品。智能体操纵画布、剧本与分镜编辑、生成工作流、恢复与同步均属于交付范围。实施工作包用于安排依赖关系，全部关键工作包完成后才达到完整验收。

## 画布中的组织与交互

提供个人画布和项目画布。个人画布可直接进行文本、图片、视频创作；要创建正式剧本、分镜和项目资产时，明确选择已有项目或创建项目并初始化工作区。项目画布固定所属项目，不以客户端传来的任意 projectId 改写归属。

同一项目允许多张画布，分别承载总览、某一集、某个场次或方案探索。一个业务对象可以出现在多张画布中，每个引用节点都有独立位置和展示方式，所有实时引用显示同一份已提交业务内容。

界面由顶部标题与保存状态、左侧项目目录和素材库、中间画布、右侧属性或阅读编辑面板、底部运行与预览区域组成。融光助手复用现有会话与停靠能力，作为可切换面板，避免同时出现两套互不相通的聊天窗口。小屏幕下属性和助手互斥展开，长表单使用可滚动 Sheet。

侧栏切换就地放置：左侧为“内容 / 素材”，右侧为“属性 / 评论 / 历史”，各自提供收起入口，不把全部切换按钮堆在右上角。窄屏使用一排明确的文字入口，同一时间展开一个面板；面板覆盖时，后方画布不能继续接收键盘操作。业务节点优先显示真实内容，画布显示名称与引用设置放在次级区域。

画布、节点、端口、工具栏、弹窗和历史快照必须跟随平台深浅主题，直接使用同一套语义颜色，不另设默认深色主题。默认保留清晰的“添加节点 / 选取 / 手形 / 查找 / 查看全部 / 整理”，小地图和业务关系作为按需视图。

2026-10-21 补充：横向工具条中的按钮、图标按钮、分段切换、开关操作项与输入框保持同高和垂直对齐。主要操作使用共享按钮的 36px 高度，收起文字或折叠低频操作时不改变高度；其他辅助工具组也不得混用尺寸。覆盖标题、画布视图、选中节点、侧栏、内容浏览器、素材、运行结果、列表筛选和镜头预览，保留完整焦点外圈，并在宽屏、窄屏与明暗主题中实测。

节点支持平移、缩放、框选、多选、连线、复制、删除、分组、折叠、对齐、自动整理、搜索定位、小地图、撤销重做、键盘操作。自动整理只移动指定范围，保留锁定位置，不在每次结果更新时重新排布全图。

鼠标新增节点有两个同等完整的入口：右键画布空白处打开可搜索、分类的节点菜单；从节点输出端口拖线到空白处，松开后自动打开适合接续该输出的节点菜单。菜单按落点的画布世界坐标创建节点，视口缩放、平移和菜单避让屏幕边缘不能改变实际落点。节点右键菜单与空白菜单区分，输入框、媒体控件中的原生编辑操作不被画布截获。

连线菜单依据同一能力目录筛选基本输入类型、单项/集合和项目作用域，展示“后续节点 · 接收端口”。首帧、尾帧均属于图片，可连接参考图片集合；模型不支持某项输入或数量超限不能隐藏可匹配节点，也不能阻止保存这种连接。多个合适端口需要明确选择，不能任取第一个；集合不能隐式变成第一项，候选选择/集合处理作为明确节点展示。选择类型后立即创建真实草稿节点，并在右侧配置；缺少模型、正文、媒体或业务引用显示“待配置”，不预填虚假参数。菜单本身不发起生成、计费或业务对象写回。

选定后一次提交创建节点和连线，并作为一次可条件撤销的命令；服务端重新检查源节点/端口、版本、权限和图约束。若源节点已删除、被修改或权限已撤销，整组拒绝，不产生孤立节点或半条连线；确定拒绝后自动解除占用并刷新状态，不锁住整个编辑区。Esc、点击外部仅关闭待选菜单；已创建节点可整体撤销。菜单使用 Portal 并限制在视口内，支持方向键、搜索、Enter、Esc、焦点恢复；工具栏菜单锚定添加按钮下方，其位置与新节点的画布落点分别计算，端口和右键菜单仍靠近操作位置。

编辑与运行分层校验：编辑期保留基本类型、端口方向/容量、DAG、权限、业务归属、版本以及已填写字段格式校验；模型输入、互斥方式和数量约束即时投影为红色曲线、节点“检查输入”和可定位的中文原因。模型及工作流版本仍可选择，输入匹配者优先，其他选项标明“输入需调整”。运行前重新严格检查配置完整性、素材状态、模型和实际输入数量，问题未解决不能提交执行。网络中断或回执不明时，后台按原 requestId 自动确认保存，标题下方显示状态；不显示占据画布的恢复横幅或要求用户选择重试/放弃。未确认写入暂时串行，画布浏览、选择和预览继续可用，不将此机制描述为完整离线编辑队列。

以上入口与智能体共用能力查询、连接校验及原子图命令。智能体可以按具体端口查询可接续节点、明确参数后批量创建并连线，回执包含真实节点、连线、版本和命令 ID；它不能绕过人工菜单受到的类型、项目、版本或权限约束。

按用户后续交互要求，缩放只改变视野和节点的几何比例，不因远景自动折叠节点正文、封面或端口。全文和复杂表单由独立面板编辑；手动分组折叠必须保留明确入口，不改变数据或执行语义。

媒体卡默认显示缩略图和封面，点击才加载视频或音频。结果比较模式支持并排查看提示词、参数、候选图与视频；可选结果固定为具体输出版本。所有非必要动画遵守 reduced-motion，按钮、Select、浮层、语义色和圆角遵守仓库 AGENTS.md。

镜头序列预览使用明确的镜头或片段顺序；拖动节点位置不会改变镜头顺序。浏览器顺序播放用于审阅，正式导出的音视频必须由后端合成产物提供，不能把多个播放器顺序切换当作导出文件。

## 节点与关系模型

节点分为业务对象、处理能力、媒体、组织与评审四类。名称和展示可以灵活，底层 kind 与 schemaVersion 必须稳定。

| 节点族 | 主要成员 | 核心数据与行为 |
| --- | --- | --- |
| 项目设定 | 项目简介、画风与参考图 | 绑定 Project，按字段更新并记录版本；运行时生成设定快照 |
| 剧本对象 | 原文、剧本、分集、场次 | 绑定 Script / ScriptEpisode / ScriptSceneItem；摘要预览、全文阅读与编辑 |
| 分镜对象 | 分镜集、场次、镜头 | 绑定 Storyboard / Episode / Scene / Item；结构编辑与媒体绑定 |
| 资产对象 | 角色、场景、道具、子资产 | 绑定 Asset / AssetItem；属性表由已有元数据定义驱动 |
| 文本处理 | 创意、提示词、文本拼接、文本生成 | 手写文本或固定模板；文本生成选择已配置模型，输出有版本 |
| 剧本与分镜处理 | 解析、故事转剧本、转分镜、资产提取、批量镜头处理 | 选择已有专业 Agent；冻结作用范围，输出实体集合和运行引用 |
| 媒体生成 | 生图、生视频、已发布 ComfyUI 工作流 | 有类型的端口、模型能力、参数、候选结果与历史 |
| 媒体处理 | 首尾帧提取、图片裁剪与缩放、片段整理 | 确定性服务端处理；保留原始媒体，产生新资源 |
| 音频与交付 | 配乐、音效、混音、有序片段合成、分集合成、导出 | 持久化任务、独立输出、试听与成片预览 |
| 选择与集合 | 候选选择、资源集合、镜头集合、批量遍历 | 有明确 itemId 和顺序，支持人工选择屏障、有限数量批处理 |
| Agent | 画布任务、剧本助手、已有专业 Agent | 显示目标、授权范围、运行和确认状态；支持查看修改结果 |
| 组织与评审 | 分组、备注、评论、检查点 | 不自动生成付费任务；分组和评论有稳定锚点 |

三个关系体系分开处理：

1. **业务关系**：分集属于剧本、镜头属于场次、镜头使用角色。这些关系来自业务数据，显示为可过滤的引用线；更改关系必须执行对应业务命令。
2. **执行数据流**：某个图片输出接入视频首帧、片段集合接入合成。这些连线具有端口类型和顺序，参与有向无环执行图。
3. **空间与说明关系**：分组、注释、排列。这些不影响生成输入或执行顺序。

执行图必须无环，业务引用图可以出现合理的双向关系。将生成结果绑定到原镜头属于一次业务写入和来源记录，不把它自动转换为要求重复执行上游的环路。

端口类型至少覆盖 text、image、video、audio、scriptRef、episodeRef、scriptSceneRef、shotRef、assetRef 及各自集合。端口声明 required、cardinality、acceptedTypes、modelConstraints；数组输入还保存显式顺序。输入绑定以 literal、resourceRef 或 connection 三种互斥形式表达，不暗中覆盖已有手填内容。

媒体端口使用 firstFrame、lastFrame、referenceImages、referenceVideos、referenceAudios、referenceDocuments 等明确用途。通用/专业 Agent 及专业帧节点保留主要业务输入与创作要求，另提供四类可选参考媒体集合端口，支持同次执行混合图片、视频、音频和文档。模型切换后重新检查连线、输入互斥、总量与传输格式；不支持的输入在计划阶段明确报错，运行被阻止。执行时按实际 MIME 再次检查并鉴权去重，通过模型声明的 Base64 或授权 URL 投影，不把媒体地址文字当作真实多模态输入，也不在持久化运行中保存 Base64 正文。

多候选输出固定到 nodeRunId、outputId 和 resourceId。依赖尚未完成的生成节点时，执行计划绑定本次运行中的指定输出策略；没有明确选择策略的多结果节点进入等待选择状态，不能任取第一项。重新生成总是产生新的运行和输出版本。

统一建立 CanvasCapabilityRegistry。每个可执行能力登记 operationKind、schemaVersion、参数 Schema、输入输出端口、适用资源范围、权限风险、数量限制、取消与重试语义，以及执行适配器。前端节点面板、Agent 工具说明和服务端运行校验都从同一个版本化能力定义生成，避免三处分别维护不同的模型规则。

渲染器与执行器分离：同一媒体生成能力可用卡片或紧凑节点展示；新增供应商沿用已有模型能力与策略路由，不新增一套画布执行器。执行适配器按业务修改、Agent 任务、媒体生成、确定性媒体处理、合成导出分类，禁止在一个大型 CanvasService 内累加所有类型的分支。

## 剧本与分镜的编辑规则

画布节点持有 entityType、entityId 和展示配置；业务正文以现有实体为唯一事实来源。节点中的摘要属于可重建投影，不成为第二套可独立保存的剧本或镜头数据。

剧本采用“总览 → 分集 → 场次”的渐进展开。原文和梗概可全文编辑；场次按对白、动作、旁白、镜头指令、环境描写的结构编辑。资产引用继续保持类型和项目边界。长正文按需加载，节点摘要和全文编辑器使用不同的数据选择器。

分镜采用“集 → 场次 → 镜头”的渐进展开。单镜头编辑包括现有业务字段；批量修改限定字段集合并先计算影响范围。支持选中镜头连续预览、缺失素材筛选、首尾帧对照、关联角色与场景检查。

用户编辑时保留本地草稿及基准 entityVersion。保存时提交字段 patch 和 expectedVersion；缺省字段表示不修改，明确清空使用对应 null 或空数组契约。冲突返回当前值与变化字段，用户或 Agent 基于新版本重新决定，不能静默覆盖。

同一对象的不同字段可以通过服务端检查后合并；同一字段并发修改必须显式处理。完整目标支持多用户及 Agent 并发修改不同对象和实时同步，对同一段文本采用版本与差异合并，不宣称已经具有字符级 CRDT 协作。

剧本实体已有版本字段，但所有写入口仍需一致携带版本条件；现有分镜、资产等缺失同等版本控制的实体需新增版本字段。批量排序锁定同一父集合并校验集合版本，避免多个客户端各自生成重复顺序。

“编辑原文”“重新解析”“替换结构”“追加分集”是不同命令。现有 replaceSourceAndReset 会删除子结构，接入画布时必须记录影响对象、旧版本和删除事件。被删除的业务对象引用显示已删除或待重新关联，不按名称、集号或镜号猜测它对应哪个新对象。

复制引用节点只复制视图；复制为独立创作对象需要显式生成新业务 ID。分支试验可以生成草稿资源或候选集合，应用时再修改正式剧本、分镜或素材绑定。创建一个不同故事版本时应有明确的草稿容器或项目副本，不能让两条分支同时改同一份正式数据而假装相互独立。

## 智能体操纵画布

画布助手是完整产品的核心能力，使用现有 AgentScope 运行体系。它需要理解当前创作内容、读取节点和关系、执行结构化命令、启动工作流、观察结果、修改业务数据和整理画布。

提供画布上下文能力，并可注册 canvas_assistant 专用 Agent。默认助手在明确绑定画布的会话中也可以加载同一能力；专业 Agent 接收作用范围和结果回写上下文。工具是否可用以注册表、Agent 白名单、用户启用选项及服务端授权的交集为准。

### 智能体获得的上下文

每次用户发送消息，携带明确的 canvasId、projectId、选中 nodeIds、当前关注的业务对象、可见区域摘要及客户端最后确认的事件序号。服务端重新读取授权后的真实数据，不把客户端传来的正文、ownerId 或权限当作可信依据。

选中集合随请求固定。执行过程中用户切换画布，不会让正在运行的 Agent 自动转而修改新画布。大画布采用概要、选中邻域、分页查询和按需读取全文，避免把整个项目正文与所有媒体塞进每轮上下文。

发送涉及当前编辑内容的指令前，前端先完成该对象草稿保存；若存在冲突或无法保存，应提示并保持草稿。也可让用户明确把草稿作为候选文本交给 Agent，此时它不是已提交的业务版本。

上下文链需要从 AiChatReqVO、AgentScope 运行上下文和子 Agent 上下文一路传到工具执行边界。除已有 userId、ownerType、ownerId 外，新增经服务端验证的画布作用域、agentRunId、toolCallId、ownerEpoch、取消标识和关联命令 ID。HTTP 入口通过 SecurityUtils.requireCurrentUserId() 取得身份，异步执行只使用已验证并持久化的身份上下文。

### 运行内核与历史恢复版本

每次受理冻结系统提示词、主动选择的 Skill 正文、模型配置及工具白名单。恢复校验规范化快照的 schema 版本、摘要、原模型版本、工具签名与实现版本；只有完整匹配才能继续。旧记录缺少必需版本或当前实现不再支持时，保留原运行、审计与已完成产物，以 `RUN_CONFIG_UNAVAILABLE` 明确结束；显式续跑返回 409。用户按当前能力重新规划并发起新运行，不能猜测旧版本、静默替换模型/工具、自动重放外部调用或通过修改历史数据掩盖不兼容。

主动引用 Skill 沿用当前账号目录及既有数量/正文限制，其内容不会扩展画布工具白名单、资源权限或服务器 Shell 能力。MCP 工作流操作必须登记并固定实际工具定义、输入/输出 Schema、服务配置指纹、副作用、幂等参数与超时；当前支持文本/JSON 输出，媒体需要另行定义托管协议。已受理但缺少完整回执时保留未知状态与名额，通过读取原调用、采用有效迟到结果或正式核实结束处理，不自动重发。

### 用户与智能体共享同一组命令

所有写操作使用统一命令信封。以下为设计示例，ID 为示意占位：

```json
{
  "requestId": "req-unique-id",
  "canvasId": "canvas-id",
  "preconditions": {
    "nodes": [{ "id": "shot-node-id", "configVersion": 6 }],
    "resources": [{ "type": "storyboardItem", "id": 123, "version": 8 }]
  },
  "operations": [
    {
      "type": "storyboard.item.patch",
      "resourceId": 123,
      "patch": { "cameraMovement": "缓慢推进", "duration": 5 }
    },
    {
      "type": "canvas.node.create",
      "clientRef": "video-a",
      "kind": "videoGeneration",
      "config": { "modelId": 42, "count": 1 }
    },
    {
      "type": "canvas.edge.create",
      "source": { "nodeId": "frame-node-id", "port": "image" },
      "target": { "clientRef": "video-a", "port": "firstFrame" }
    }
  ]
}
```

这是编辑命令，不会隐式触发付费生成。运行使用单独的 plan 和 start 命令，并固定图和业务输入版本。actorUserId、origin、agentRunId 与审批事实由服务端从认证及运行上下文取得，不能由模型参数自行声明。

一个本地编辑命令组在单个数据库事务中校验、写入并记录审计；组内任何操作失败则整体回滚。长时间模型调用、上传、转码不放入此事务。跨长任务的工作流采用分步状态机，每一步记录提交结果，失败后保留已完成产物。

requestId 在明确的主体和画布作用域内唯一，重复请求返回原有提交回执。独立节点的修改使用节点或实体版本进行并发判断，避免一次拖动导致整张画布的所有编辑都冲突；跨集合排序和拓扑修改另校验对应集合版本。

前端可以乐观呈现拖动和轻量编辑，但以服务端提交回执和事件为准。相同 commandId 的本地回执与 SSE 事件只能应用一次。模型输出的说明文字不会被前端当成可执行 JavaScript、SQL 或任意补丁运行。

剧本文字、素材中的可识别文字、Skill 引用资料和 MCP 返回内容属于任务数据，不能单独授权扩大操作范围。Agent 只能使用经本次运行作用域与用户权限校验的能力。用户可以明确要求扩展范围，此后由服务端更新作用域并重新检查相关资源。

### 授权与变更可见性

沿用现有 DEFAULT、ALWAYS_ASK、ALWAYS_ALLOW、FULL_ACCESS 四种工具执行模式，保留各自语义。FULL_ACCESS 不绕过数据归属、版本约束、服务端预算和取消检查；它只影响工具确认策略。

通用批量操作工具必须根据 operations 中最敏感的动作计算 getPermissionRisk，并实现 mayRequireHighRiskApproval。不能因为工具名没有 delete，就把删除剧本、清空场次或覆盖分镜降为普通编辑。

确认界面基于具体命令展示新增、修改、删除对象和预计生成数量。批准绑定命令内容摘要、输入版本和有效期；内容或范围改变后，旧批准不能被复用于新命令。已经符合当前授权模式的普通编辑直接执行，不为每次节点拖动或每个字段额外增加确认。

Agent 操作结束后，画布高亮实际变化的节点，运行面板展示被修改字段与对象，支持定位、差异查看和撤销可撤销的变更。隐藏的模型推理不作为审计内容；审计记录工具请求、提交事实、业务差异和任务结果。

## 人工与智能体的同步协议

整体数据流为：用户或 Agent 发出命令 → 服务端检查身份、资源权限、版本和幂等 → 事务写入业务数据、画布变化及 Outbox → 投递已提交事件 → 所有授权客户端更新对应对象。

需要为普通业务写入建立资源变化事件，例如 resource.updated、resource.deleted、resource.bindingChanged。画布维护业务引用索引，能定位所有引用某个实体的节点。普通剧本页修改场次后，相关画布收到同一实体的新版本；画布修改分镜后，普通分镜页也按资源事件更新。

现有 TOOL_INVALIDATION_MAP 只按工具名称刷新 assets、scripts、storyboards，无法表达哪一个对象改变，也无法覆盖后台 worker 的更新。完整方案使用服务端提交的资源事件；旧页面在改造过程中可将资源事件映射为已有模块刷新，但不能再只靠工具名称判定数据是否变化。

持久化事件具有 eventId、canvasId、sequence、commandId、origin、resourceVersion、nodeRunId、eventType 和 typed payload。每张画布的提交事件序号单调增长，客户端按序去重；资源投影另按实体版本防止旧事件覆盖新内容。

初次打开画布读取一致性快照和 highWaterSequence，然后订阅 afterSequence 之后的 SSE。服务端先补发持久化事件，再进入实时流，消除读取快照与建立订阅之间的遗漏。断线后从已处理序号续读；事件保留期已过时返回明确的 snapshot-required 协议，让客户端重新取得快照和续读位置。这是显式恢复流程，不能静默显示未保存或过期内容。

画布数据流与 Agent 对话流具有不同的序号和生命周期。通过 canvasRunId、agentRunId、commandId、toolCallId 关联展示，不混用游标。聊天流完成不代表媒体生成任务已经完成，画布流仍按数据库终态推进。

当前视口、光标、节点悬停和临时选择属于用户或会话级状态。共享的是业务数据和已提交节点位置。多人在线位置可作为低频、可丢弃的存在信息发送，不写入完整业务操作历史。Agent 聚焦请求只作用于发起会话，用户手动移动视口时可以不跟随。

## 工作流与长任务执行

完整目标包含单节点、选中子图、指定目标及其依赖、整条流程、仅失效节点等运行方式。CanvasRun 保存图快照、作用范围、资源版本、参数、模型能力快照和输入选择策略。运行中的编辑形成新的文档状态，不修改已经启动的运行快照。

执行前构建计划，展示会运行哪些节点、哪些复用历史输出、哪些等待用户选择、哪些更新正式业务对象。付费媒体生成默认产生新结果；复用历史产物需要固定有效的输出版本和明确策略，不能仅凭提示词相同就视作生成已完成。

状态区分文档草稿、输入校验结果与运行状态。建议节点运行至少具有 WAITING_INPUT、READY、QUEUED、RUNNING、WAITING_SELECTION、WAITING_CONFIRMATION、SUCCEEDED、PARTIAL_FAILED、FAILED、CANCEL_REQUESTED、CANCELLED 和 UNKNOWN_SUBMISSION。结果是否因输入变化而过期，作为独立 derivedState 表示，不能改写原运行成功事实。

调度器只执行数据流依赖；上游失败时阻止依赖它的分支，独立分支可以继续。多候选选择、需要编辑授权或需要用户确认的正式回写，作为可持久化等待点处理。批量任务先冻结目标 ID 列表与数量上限，再为各目标创建子运行，避免动态增长集合导致无限执行。

批量处理使用明确的“处理方式 → 逐项输入 → 汇总输出 → 最大数量”表单，内部参数复用该处理节点的模型/媒体配置。计划按最大数量核算预算；实际执行原子冻结有序目标，子项分别持久化并关联 parentNodeRunId、itemIndex、attempt。恢复不能重新展开或重复提交；重试须明确选择失败项的新 attempt，成功项不重做，所有重试仍计入原预算。部分失败等待用户选择采用已有结果继续、重试失败项或结束批次；未知受理先核实原外部任务。运行 UI 展示逐项状态、原输入顺序与历史尝试，不能用一个进度条隐藏部分失败。

正式写回使用独立“写入业务内容”节点，分别连接一个明确结果和目标业务对象。选项仅来自登记字段，先持久化原值、新值、版本、影响范围和提案摘要，再等待批准或跳过。批准时重新校验权限、原目标及父版本、提案摘要、取消与期限，经共享业务命令在同一事务内写入并发布新版本；跳过阻断此分支。剧本原文替换必须按既有业务语义展示将重置的分集/场次并取得对应确认，不能伪装成普通文本覆盖。智能体只能提出与等待这份提案，敏感写入仍须绑定真实人工批准。

生成、合成和音频任务使用共享提交与任务追踪体系：

1. 创建业务任务、结果条目、CanvasNodeRun 关联和 Outbox 必须保持事务一致性。
2. 可靠投递后由工作者原子领取；领取带 owner、lease、epoch，旧执行者不能覆盖新执行者结果。
3. 供应商受理后保存每个结果条目的远端任务 ID，后续调度按 nextPollAt 单次查询，不让请求线程或 Agent 工具持续睡眠等待。
4. 成功结果完成托管和资源登记后才对下游宣布可用。资源存储失败属于任务失败或明确的待完成步骤，不发布失效外部地址冒充完成。
5. 更新终态与结果事件在同一数据库事务中提交；Outbox 重放及重复回调均幂等。
6. 任务超时、工作者重启、多实例争抢、取消与完成竞态分别有明确状态转换。

这项工作应合并既有“ComfyUI 任务异步轮询”待办，逐一适配当前平台已接入的远端任务协议。Agent 事件 Outbox 和租约模式可供复用设计，但生成任务不能借用 Agent 会话表充当自己的任务真相。

模型并发限制一直持有到远端任务进入确认终态，不能在请求提交后提前释放。按模型设置执行上限，并补充用户、项目与单次画布运行的数量约束。供应商未提供实际金额依据时，用图片数量、视频秒数和最大节点数约束开销，金额显示为未配置。

API 请求因网络超时而结果不明时，先根据幂等标识或已有供应商任务 ID 对账。供应商不支持查询或幂等的受理窗口进入 UNKNOWN_SUBMISSION，由明确的重试决策处理，不能宣称可以在任何第三方条件下保证恰好一次扣费。

2026-10-16 按用户反馈明确失败边界：供应商提交接口已返回非成功 HTTP 响应（包括 503 队列已满）时，直接持久化为 FAILED，保留可读的实际错误原因并释放该请求名额；依赖它的后续步骤结束等待，独立分支和画布编辑继续可用。此类已知失败不进入 UNKNOWN_SUBMISSION，不要求用户确认“是否受理/是否结束”，也不提供反复读取同一失败回执的无效操作。用户可按原范围显式重试并复用成功步骤；没有收到响应或工作者中断后缺少回执才属于上述结果不明边界。供应商认证错误不能冒充本平台登录过期，正文中的密钥、堆栈和错误页面不直接展示。

取消含义要分开：取消排队、请求远端取消、停止后续分支，以及停止 Agent 的进一步编辑。远端不支持取消时显示仍在结束中的真实状态，不把取消请求当作供应商已经停止。节点删除不删除正在进行的执行记录，也不会在完成时把已删除节点重新插入画布。

### Agent 与异步工作流衔接

当前 generate_image、generate_video 使用 submitAndWait。画布的 run_canvas_nodes 先返回已持久化的运行引用；如果 Agent 还需依据生成结果继续工作，await_canvas_run 将运行、toolCallId、等待的结果和恢复检查点持久化。

已有 AgentWaitingStatePort 提供 enterWaitingExternal 与 resumeExternal，可据此实现画布任务等待适配器。仍需完成任务完成通知、内部恢复者身份、检查点格式、终态去重、取消传播和恢复后执行的集成，不能只设置一个 WAITING_EXTERNAL 字符串。

生成完成后，服务端用结构化结果恢复原 Agent，Agent 再读取新资源和版本，执行选图、回填或下游操作。等待期间不持续消费模型 Token，也不依赖浏览器在线。多个子任务返回时按持久化依赖计划收敛；父任务取消后阻止未获授权的后续写入。

专业 Agent 节点和可重复执行的确定性生成节点分工明确：Agent 负责需要语义理解与编辑决策的工作，调度器负责已经确定的依赖、参数、状态和执行顺序。对资源的写入全部走同一命令层，并在提交边界再次校验运行租约和取消状态。

## 数据与服务结构

完整目标采用节点、连线、命令日志、运行记录分别持久化，命名检查点保存图快照。节点 config 使用有版本的 JSON，坐标与业务对象索引使用结构化字段。整图 JSON 适合快照和模板导出，不作为并发协作时唯一的可变存储。

| 表或记录族 | 主要内容与约束 |
| --- | --- |
| afv_canvas | 名称、ownerType、ownerId、projectId、schemaVersion、结构 revision、事件序号、归档状态 |
| afv_canvas_node | 稳定 UUID、canvasId、kind、布局、分组、配置版本、布局版本、业务引用、删除标记 |
| afv_canvas_edge | 源目标节点与端口、关系类型、输入顺序、固定输出引用、版本；校验同画布与端口约束 |
| afv_canvas_operation | requestId、主体、来源、命令类型、影响对象、前后差异、结果回执、run/tool 关联；支持有条件撤销 |
| afv_canvas_event | 每画布唯一 sequence、事件类型与提交信息；用于回放和同步 |
| afv_canvas_revision | 命名检查点和图快照，包含业务版本引用，不擅自恢复所有业务正文 |
| afv_canvas_run | 执行范围、图和输入快照、状态、配置、预算、发起人与幂等键 |
| afv_canvas_node_run | 节点、尝试次数、输入与输出快照、依赖、状态；显式关联 imageTask、videoTask、agentRun 或 mediaTask |
| afv_media_resource | 类型、存储定位、托管 URL、封面、尺寸、时长、来源、所有者、内容校验信息；不存媒体二进制 |
| afv_media_reference | 资源被节点、结果、业务对象或导出包引用的关系，为删除和清理提供依据 |
| afv_resource_revision | 业务对象的可审计内容快照与版本，支持查看差异、冲突处理和针对性恢复 |
| afv_async_outbox | 生成任务投递和业务变化通知的待投递记录、去重键、重试与领取状态 |
| afv_remote_generation_job | 远端任务 ID、nextPollAt、截止时间、领取者、租约、epoch、尝试次数和最后错误 |
| afv_canvas_comment | 锚定节点或业务版本的评论、回复与解决状态 |
| afv_canvas_member | 需要画布独立共享时的权限补充；项目画布以项目授权为基础，不复制出互相矛盾的项目成员表 |

具体物理拆分可在数据库设计评审时合并同职责记录，但命令、事件、业务版本、执行记录四类生命周期不能混为一个字段。任务数据库主键、任务公开 taskId、供应商任务 ID 和 canvasRunId 使用不同类型或字段，避免当前多种 taskId 含义混用。

数据库约束至少覆盖每画布事件序号唯一、主体作用域内 requestId 唯一、同一次运行内 nodeId 与 attempt 唯一、相同任务来源的重复投递去重，以及单值输入端口的唯一有效绑定。业务引用索引用于按 entityType 与 entityId 定位所有画布节点；活动任务按状态、nextPollAt、leaseUntil 建索引。大正文与快照分开分页读取，画布列表不加载整图与运行历史。

媒体引用规则：已有图片、视频和资产来源通过授权的来源适配器登记为 resourceId；来源归属从业务对象确定，不从 URL 文本推测。旧业务 URL 字段由受控的绑定命令同步更新，画布不能再另写一份不可追踪的地址。新生成和上传从完成时就登记资源。保留原媒体与必要历史，文件清理必须在所有引用消失且超过保留期后执行。

对历史资产 properties 中的视频地址使用明确的导入映射规则，记录 sourceType、sourceId 和原始字段。未知类型或不完整来源返回需要处理的错误，不猜测媒体类型，不静默改用其他地址。

建议新增 CanvasQueryService、CanvasCommandService、CanvasAccessPolicy、CanvasProjectionService、CanvasEventService、CanvasRunService、CanvasScheduler、CanvasAgentContextService。业务侧补充 ResourceCommandService 和 MediaResourceService，生成侧抽出 GenerationSubmissionService 与 RemoteGenerationJobService，合成侧抽取接受有序媒体输入的 MediaComposeService。

新增服务及现有服务改造遵循项目缓存规范，通过 @Cacheable / @CacheEvict 管理明确的资源缓存。频繁任务状态和大画布内容不能依赖无边界全量失效；缓存键需体现资源 ID 或版本，权限判断不能因为缓存命中被跳过。

## 前端与代码组织

建议路由为 /canvases、/canvases/{canvasId} 和 /projects/{projectId}/canvases/{canvasId}。后两种入口复用同一编辑器，客户端输入 projectId 不代替服务端画布归属。

共享画布实现放到前端 components/canvas，路由编排保持轻量。组件按 CanvasWorkspace、CanvasSurface、CanvasToolbar、NodePalette、ResourceBrowser、Inspector、ScriptEditor、StoryboardEditor、MediaPreview、RunPanel、HistoryPanel、AgentPanel 和节点渲染器拆分。路由专用部分放 _components，共享业务编辑器从原剧本、分镜、资产目录提取到跨页面目录。

状态分为图文档、业务对象缓存、执行状态、编辑草稿、视口选择、助手会话六部分。节点只订阅自身数据和相关输出；Agent 流式文字不会引起全画布重绘。临时 viewport 与持久化 node position 分开，布局变化不改变输入 hash。

现有 generation-workbench.tsx 980 行、剧本 page.tsx 781 行，均不适合直接加入画布分支。先抽出生成参数、能力校验、编辑器、业务 hook 和 API 适配，再让普通页与画布复用。遵守单文件 1000 行上限及页面、组件建议长度，不修改 components/ui 下基础组件。

画布是固定剩余高度的工作区，沿父级使用 grow basis-0 min-h-0。公共 main 和覆盖式 ScrollArea 保持项目约束，画布中央由 React Flow viewport 平移与缩放；属性、运行和阅读面板按明确独立栏位滚动。浮层通过 Portal 显示，输入区与播放器隔离拖动和滚轮事件。

React Flow 支持自定义 React 节点，适合复用 Shadcn 表单和媒体组件；自动整理可参考官方 ELK 示例，在独立 worker 计算，再以一次批量布局命令提交。布局结果携带输入节点版本，计算期间节点发生变化时重新检查，不能把旧计算覆盖用户新拖动的位置。[自定义节点](https://reactflow.dev/learn/customization/custom-nodes)、[ELK 布局示例](https://reactflow.dev/examples/layout/elkjs)

视口裁剪和节点 memo 化需实际测试收益，配合按集和场次折叠、缩略图、有限播放器和连线简化。React Flow 官方提醒频繁订阅全量 nodes/edges 和复杂节点样式会放大重渲染开销。[性能建议](https://reactflow.dev/learn/advanced-use/performance)

## 权限与资源边界

画布权限至少区分查看、编辑、执行、管理。项目画布继承合法项目访问范围，再检查具体操作权限；个人画布按所有者及显式共享成员授权。现有 canAccessProject 只能作为读取访问判断的一部分，不能直接等同于写入权限。

读取、运行、下载、事件订阅、导出、历史恢复都检查画布与底层资源权限。跨项目素材引用需显式导入或授权，画布分享不会自动赋予其他成员访问私人图片、Agent 会话、Skill、MCP 密钥的能力。后端工作者在调度和正式业务提交时处理权限撤销，不允许失效身份继续发布结果到无权访问的对象。

任意外部 URL 导入通过受限的后端媒体获取流程，校验协议、地址、重定向、类型和大小。画布文档不承载 API Key、临时 Bearer Token、浏览器 blob URL 或大段 Base64 媒体。模型输入的 URL / Data URI 传输在后端根据已有能力契约完成，配置不满足时明确阻止运行。

现有 /media 静态资源访问方式并不等同于受 ACL 保护的私有媒体。需要私有共享的资源必须接入鉴权媒体网关或有期限的签名访问，并配合供应商可访问的受控输入地址。不能只给画布接口加鉴权就声称历史公开地址已经变成私有。

用户 Skill 和 MCP 的能力沿用已有授权和用户隔离。任意导入的 Skill 脚本不通过画布获得服务器 Shell 权限；脚本沙箱仍属于独立的既有待办。为可执行 MCP 节点登记参数、输出、超时、幂等和副作用契约；缺乏契约的工具仍可在助手中按权限使用，但不能冒充可稳定重放的工作流节点。

## 完整使用场景

**从故事到成片。** 用户输入故事和画风 → Agent 创建或绑定项目 → 故事转剧本节点生成集和场次 → 资产提取和子资产准备 → 转分镜 → 用户在画布直接修改对白与运镜 → 批量生成首尾帧 → 选择候选 → 批量生成镜头视频 → 片段排序 → 配乐、音效与混音 → 合成与下载。整个过程的正式业务内容、结果版本和运行来源可以查询。

**修改一组镜头并继续生成。** 用户框选镜头，要求“改为雨夜，保持角色造型，重新生成这些镜头的视频” → Agent 固定选中对象和版本，查询角色、场景、模型能力 → 提交镜头字段及相关参数修改 → 创建或更新对应生成节点 → 提交具体运行计划 → 根据权限模式执行 → 异步等待 → 展示新旧结果比较 → 按明确策略应用结果。未选中的集和镜头不被隐式纳入。

**局部探索与选定结果。** 用户将同一首帧分成两条模型分支 → 独立生成、预览与比较 → 固定一个输出应用到分镜 → 原分支、提示词和运行历史仍保留。复制分支不会复制或重跑上游付费任务，除非运行计划明确要求。

**智能体整理现有项目。** 用户要求“把第二集的剧本、角色、分镜和视频整理到画布，并标出缺少首帧的镜头” → Agent 查询已有业务资源 → 批量创建引用节点与分组 → 显示业务关系和缺失状态 → 自动整理指定范围。该操作只组织已有内容，不隐式生成素材。

**多人和 Agent 同时工作。** 用户 A 修改场次对白，用户 B 修改另一个镜头，Agent 正在生成参考图 → 各自命令成功后通过事件同步 → 修改同一字段时返回冲突 → 生成任务继续使用提交时的快照，新编辑只使相关未来结果标记待更新。聊天窗口关闭不影响已持久化工作流。

**重新解析已有剧本。** 系统先展示将替换的集、场次和关联引用 → 按权限策略批准具体替换 → 记录旧结构及新 ID → 旧引用明确显示失效，提供对照与重新关联操作 → 已生成媒体保留并可再次引用，不因剧本结构更新而丢失。

## 媒体基础实施决策（2026-10-12）

新登记媒体以不可变 UUID 引用，元数据与私有存储对象分离；URL 只在需要预览、下载或模型输入时按访问用途签发。上传幂等、接收租约、状态事件、资源归属及实际媒体信息由后端登记，浏览器提交的 MIME/文件名不能替代内容检测。独立用户上传属于个人作用域，团队上下文上传属于该团队，项目上传从项目确定所有者；既有业务来源的导入必须从来源对象继承归属，不能仅凭一段 URL 或当前选中的团队猜测归属。

存储后端可能已有公开读取策略，因此新增托管文件使用 Tink Streaming AEAD，读取端使用其可寻址解密通道支撑视频 Range。密文位于已配置的本地/S3 存储，密钥集只在服务端数据库保存；数据库与密文需一并备份，不能把“对象存储只含密文”描述为数据库密钥本身已有 KMS 托管。采用标准库的流式认证加密及官方推荐参数，不自行实现媒体分块密码协议。[Tink 大文件加密](https://developers.google.com/tink/encrypt-large-files-or-data-streams?hl=en)、[Java StreamingAead 接口](https://github.com/tink-crypto/tink-java/blob/v1.23.0/src/main/java/com/google/crypto/tink/StreamingAead.java)

浏览器凭据有效期为 5 分钟，绑定单个资源/版本及签发时的用户、团队，数据库只存凭据摘要。内容网关每次检查资源状态和当前权限，长传输按间隔重验；预览端应在到期前申请新地址，不能把带凭据地址写入画布文档或业务永久字段。供应商访问还须绑定持久化运行、限制生命周期并检查模型输入协议，此路径后续与运行引擎一起接入。

接收进程退出后，后台依据数据库时间将到期 STAGING 状态转为可重试的 FAILED；新尝试使用新代数和新对象，不能覆盖先前文件。ORPHAN 对象在完整引用与保留策略实现之前不自动物理删除。历史 /media 和其他公开地址必须明确标记为历史来源，不能因新网关上线就宣称其公开地址已被收回。

## 来源批量导入实施决策（2026-10-14）

来源导入使用持久化 `SOURCE_IMPORT` 媒体任务，每批 1–50 个明确的业务/生成字段，受理时固定来源版本、所有者、字段和预留节点 ID。HTTP 只受理请求，Outbox 投递后才由工作者领取；每次领取处理一个来源，并保存分项结果后让出工作者。部署范围最多同时处理 4 批、同一账号最多 2 批，单实例最多 2 个工作者；租约、代数、截止时间和取消状态均由数据库判断。

浏览器在请求前保存原请求和账号/团队/画布范围，未确认请求只能继续原内容或撤回；撤回早于受理时阻止迟到请求。成功项不因同批其他项失败而丢失；用户显式选择失败/停止项重试，原成功项保持不变。读取、登记和发布阶段检查来源及执行身份，分集合成读取历史视频也使用同一任务保护。

## 私有媒体预览实施决策（2026-10-14）

图片与视频卡片按可见区域请求 `canvas_640_v1` 预览。后端以原媒体 ID、版本和预览规格唯一受理持久化任务，多个画布或成员共享同一结果；失败保留原因并等待显式重试。任务使用 Outbox、租约、epoch 和接收检查点，完成登记后才发布缩略图。图片等比缩到 640×480 以内，不放大小图；视频取时长 10% 与 1 秒中的较小值，返回实际采样时间。卡片不提前加载原视频播放器。

预览是私有托管派生媒体，始终重验原媒体版本、状态和当前读取权限；子文件所有者、业务绑定或全局预设不能绕开原媒体授权。派生文件不出现在普通素材库，也不能再次作为缩略图来源。只读成员可以请求预览，但不能借此上传任意素材。原图或原视频的完整预览、下载仍走原文件票据。E 的视觉观察必须传递预览规格与采样时间，不能把单帧当作已观察整段视频。
