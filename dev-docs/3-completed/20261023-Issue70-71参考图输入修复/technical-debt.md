# 维护边界

- 本地读取仅覆盖与 resource_base_url 完全匹配的本站旧式媒体路径和内置画风图；托管媒体继续经过现有资源标识与权限校验，不使用此功能绕开授权。
- ComfyUI 工作流由管理员导入、验证和发布；不自动改写用户图结构、模型权重或 LoRA，不把原厂最大参考图数量直接当成工作流实际容量。
- 回归验证使用本地桩服务，不替代真实 ComfyUI GPU 出图、显存或画面一致性验收。
- 该修复不会自动扩大或重写已经发布的工作流，也不擅自把已保存的模型上限改为 4 或 16；需要新增槽位时先修改实际图结构与绑定，再同步模型配置。现有模型选择流程已经按绑定索引推导数量。
- 新检查要求已提供的媒体全部被绑定；原先依赖“传入多张但只消费部分”的配置会明确报错，需要修正输入或绑定。明确的 string_list 整表绑定继续保留。
- 容器路由核验使用真实 Nginx 与桩上游，不代替报告者的完整部署复现。当前 main 文件与工作区的默认转发一致，但 latest 镜像、外层代理和用户保存的模型能力尚未取得，不能把已修复的独立协议头问题认定为该报告的唯一根因。
