# 技术债务与边界

- 覆盖配置归当前用户，不修改全局内置定义，也不改变工具或子 Agent 的注册方式。
- 覆盖配置不提升项目权限、不扩大已受理画布作用域、不解除数量预算；画布执行保留自动批准策略。
- 默认不限步数；用户可为单个智能体设置显式上限。网络/媒体操作的独立超时不在本需求中改变。
- 不新增静默 fallback；不存在或不可访问的工具、Skill 应在保存或计划阶段给出明确问题。
- 真实外部付费模型调用须遵循既有用户授权，自动化验收优先使用隔离数据库与本机可控模型。

## 历史运行兼容边界

本次新增配置字段之前已受理的 Kernel 快照没有用户覆盖与 Skill 正文。恢复这些历史执行仍使用它们原有的内置定义/无新增 Skill 语义，不读取后来保存的用户配置。此分支用于用户明确要求的历史执行与对话恢复兼容；新受理任务必须携带完整快照，缺失条目会报错，不静默替代。旧画布计划在新配置指纹下显示输入变化，重新执行前必须重新预览。

## 验收环境与数据

仅使用独立验收数据库 51055、Redis 51057 与 localhost:3023/18092。Chrome 创建了个人 Skill `config-audit-continuity`（配置验收 · 连续性检查）用于验证选择与恢复，保留在本机验收账号中便于后续测试。智能体覆盖与原画布节点配置将在验收后恢复原有继承方式。没有更改生产服务或真实模型密钥。
