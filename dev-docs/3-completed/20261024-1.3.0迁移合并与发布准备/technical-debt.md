# 维护边界

- 本次调整只适用于尚未发布的 1.3.0。正式发布后，合并后的迁移即成为不可变历史。
- 已执行原开发迁移的本地数据库不能直接重新执行合并脚本，也不能只运行 repair。必须备份、确认实际结构与数据处理结果，再同步本版本历史并完成 validate。
- 同一 Docker MySQL 中还有其他项目数据库，本次只处理 ai_fusion_video；其他开发和验收容器不在本次历史同步范围内。
- 原先从某个 1.3.0 中间迁移开始的测试，需要按正式升级边界或最终数据约束重新组织，不能为了保留无效测试而继续携带已合并的开发迁移。
- AgentScope 2.0.4 在初始化 MySQL 状态存储时自行维护 version 字段，本地数据库中的这个字段不属于迁移遗漏，本次保留原状。
- MySQL 会保留下游视图创建时的字段元数据。旧开发迁移多次替换上游视图后，下游视图的可空性等元数据可能与最终定义不一致，因此历史同步同时按依赖顺序重建四个最终视图。
- 删除的五条数据回填只针对本版本刚创建的表，从正式版本升级时没有需要处理的记录；已有图片、视频任务的个人归属回填和必要初始化数据仍然保留。
