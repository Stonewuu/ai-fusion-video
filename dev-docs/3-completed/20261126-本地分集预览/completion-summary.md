# 剧本原文在浏览器中预览

导入窗口使用浏览器后台线程识别章节、分集和字数边界。选择文件、粘贴原文和检查分集时，原文都留在浏览器。关闭窗口会结束正在进行的识别。读取已有分集目录失败时，仍可继续预览，刷新目录后可确认导入。

确认导入时，页面将调整后的全文、标题和分界一次发送到保存接口，最多等待 120 秒。本地开发服务器转发 API 请求时也允许等待 120 秒。后端继续校验权限、剧本版本和分集范围，并按请求标识处理重试。

## 验证结果

- Chrome 读取 3,731,117 字的 TXT，以自动识别、每集最多 20,000 字生成 1,370 集。逐集比较浏览器后台线程与 Java 拆分器的输出，标题、起点和终点全部一致。
- 单独阻断测试标签页的已有分集目录请求后，仍可查看整本原文的分集预览。Chrome 记录中只有目录读取，没有原文提交；恢复连接并刷新目录后可保存。
- 使用另一份 4,201,292 字的测试原文修改标题并删除一集。两次预览均没有向后端发送原文，确认导入时发送了一次保存请求。测试服务延迟返回，Chrome 在 35.7 秒后收到成功响应。临时数据库保存了 99 集、4,159,280 字，逐集核对标题、顺序和正文摘要均一致。
- 前端测试、TypeScript 检查、修改文件的 ESLint 检查及生产构建通过。
