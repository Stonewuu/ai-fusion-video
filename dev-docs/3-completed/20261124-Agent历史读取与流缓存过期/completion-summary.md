# 交付总结

2026-11-25 完成。分支 `feat/agent-redis-stream`，本地前后端已运行新代码，尚未提交或发布。

## 最终行为

- 智能助手和 Pipeline 重连先接收 MySQL 完整消息及当前控制状态，再补齐 Redis 草稿并跟踪后续增量。历史读取保留消息顺序、工具参数和父子归属，不展示子任务内部输入。
- 每条共享流在全部父子运行结束、终态消息提交后保留 24 小时。运行、等待确认和等待外部工具期间不过期。配置项为 `fusion.agentscope.v2.stream-retention`，默认一天。
- 流、序号、去重索引和控制位置使用同一固定截止时间；重复查看不延长期限。启动时也为已有流补齐原结束时间对应的剩余期限。
- Redis 过期后，完整消息仍从 MySQL 重建。携带旧读取位置的重连可以接收历史快照；状态查询不再发布事件或重新创建旧流。原会话续聊使用新的运行 ID 和 Redis 流，模型上下文继续使用原有 AgentState 保留规则。
- 取消前已经输出的内容保存到 MySQL。独立子任务取消按子运行状态归类；父任务取消不覆盖已完成子任务的状态。

## 关键实现

- 协议 2 增加连接初始化用的 `HISTORY` 快照，不把快照作为新的 Redis 事件保存。快照中的数据库消息和控制状态通过同一个读取事务获取；消息身份过滤同时覆盖快照之后才发布的已提交消息，避免数据库提交与 Redis 发布之间产生重复。
- 过期检查由终态消息事务的提交事件触发，独立于被取消的执行订阅。因此父任务先结束、最后一个子任务稍后结束且没有前端连接时，也能设置期限。
- 历史查询带回子运行终态，前端区分“子任务已结束”和“父工具返回已收到”，保留完成与取消的准确分类。Pipeline 续跑时保留已有历史前缀。
- 历史协议 1 保留原有 MySQL 事件重放。没有新增数据库迁移。
