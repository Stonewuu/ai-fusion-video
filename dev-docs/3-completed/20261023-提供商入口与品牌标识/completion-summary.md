# 提供商入口与品牌标识交付总结

完成日期：2026-10-23。本次按用户反馈简化上一版赞助商接入流程，后端协议、鉴权、能力范围和保存合同未变。

## 最终流程

| 用户操作 | 行为 |
| --- | --- |
| 添加 API 配置 | 直接打开新建表单 |
| 选择普通提供商 | 自动填写对应地址和协议 |
| 点击赞助商配置 | 进入该平台快速配置，填密钥并选择模型 |
| 已有赞助商获取模型/添加模型 | 自动读取保存连接的候选，无需再次点击读取 |
| 读取失败 | 显示原因和重试，并保留手动配置入口 |
| 手动补充未知模型 | 预填精确代码、类型、协议及关联账号 |

赞助商条目统一显示标签、Logo 和获取密钥链接，链接仍从目录 credentialUrl 读取。快速配置能力继续由 quickSetup 决定，不与 sponsored 展示标识混用。

## 组件组织

- ProviderPresetPicker 负责常用平台、赞助标签和链接。
- ProviderConnectionFields 负责快速配置的名称、密钥及高级地址字段。
- useProviderModelDiscovery 管理读取、失败和在途请求复用，防止自动读取被重复发起。
- ProviderSetupDialog 只编排连接与模型两阶段；已有连接直接进入模型阶段，共用 ProviderModelPicker 和保存接口。
- 删除 ProviderSetupOptions，页面统一持有明确的配置目标，不保留旧选择页分支。
- ModelVendorIcon/ProviderVendorIcon 集中管理品牌图标；模型匹配仅用于展示，不影响协议路由。两家官网 PNG 使用 Next Image 优化，其余使用已有图标库。

## 验证与边界

TypeScript、组件 ESLint 和定向 diff 检查通过。实际页面覆盖两家新建、已有账号自动读取、错误重试、原表单数据保留、未知候选手动预填，以及明暗/桌面/窄屏的焦点、错误、禁用与长内容滚动。
