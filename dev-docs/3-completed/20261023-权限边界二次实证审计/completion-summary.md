# 权限边界二次核查与修复

完成日期：2026-10-23。

## 核查方式

本轮以当前工作区为准，继续追踪控制器、服务及持久化授权链。最初按用户要求在临时 MySQL、Redis、测试账户和本地提供商中验证疑点；用户随后要求尽量避免攻击式操作，后续停止新增攻击式复现，以代码审查和本地回归完成工作。所有验证均未涉及生产数据、线上账号或付费供应商。

本轮确认并修复 **1 处对象越权、4 个业务/会话 bug**。普通接口缺少表面上的权限注解、同团队共享或仅返回成功响应，均未直接视为漏洞。

## 确认的对象越权

### 被移出项目的任务创建者仍可删除生成记录

有效业务链：项目所有者添加编辑成员 → 成员通过真实生成接口提交任务 → 本地受控提供商完成生成 → 所有者移除成员。此时该成员读取生成任务返回 403，但删除同一任务返回 200，所有者后续读取该任务返回 404，证明确实发生了未经授权的数据删除。影响对象是生成任务记录及条目，不据此声称底层媒体文件已被物理删除。

根因：图片和视频删除服务只比较任务创建者 userId，没有检查其当前项目/团队访问权限；HTTP 和 AI 工具共用这一路径。

修复：删除服务显式接收完整 CanvasActor，GenerationDeletionGuard 在账户、团队、项目范围锁内重新授权，再进入任务删除；使用 READ_COMMITTED 防止等待锁后沿用旧权限快照。图片、视频及对应 AI 工具都传入可信身份，保留原有创建者限制、任务终态和画布运行引用保护。

修复后同一测试中，撤权后的删除返回 403，所有者仍可读取任务及生成条目。重新授予项目访问后，原创建者可正常删除。未通过全面禁止删除来使测试通过。

## 确认的业务与会话 bug

| 问题 | 修复前的实际结果 | 修复 |
| --- | --- | --- |
| 刷新凭据并发消费 | 同一个刷新凭据产生 5 组成功响应，5 个新访问令牌均能读取当前用户信息 | Redis 原子 getAndDelete 消费一次；重复消费返回真实 HTTP 401；保持不同登录会话的隔离 |
| 重置凭据重复消费 | 同一个已签发的重置凭据并发成功改密 5 次，只有最后密码可登录 | 在请求参数校验后原子消费重置凭据，只有一个请求能写入密码 |
| 重置与登录密码规则不一致 | 重置接口接受短密码并返回成功，但登录接口拒绝该密码，返回 400 | 重置新密码及确认密码统一为现有注册/登录的 6–32 字符规则；格式不合规时不消费凭据，不改变旧密码 |
| 移除成员后无法重新邀请 | 正常移除再添加返回 500；软删除记录仍占用 `(team_id,user_id)` 唯一键 | 在现有团队授权与事务中恢复已移除记录，使用本次指定的角色、启用状态和加入时间；验证重新邀请为普通成员不会恢复旧管理员角色 |

重置凭据测试仅用 Redis 夹具代替邮件投递，凭据结构与生产签发流程一致；密码校验、HTTP、数据库及 Redis 消费逻辑没有模拟。前三项属于会话/业务一致性问题，不计为跨用户对象越权。

## 前端联动

普通 HTTP 与 SSE 原有两个独立刷新队列。服务端刷新凭据改成单次消费后，合并为共享刷新协调器：同一页面的并发请求共用一次换发；其他标签页消费凭据后等待它实际发布的新会话；迟到的旧响应不能重新登录已退出的账号，也不能覆盖新切换的账号。仅复用真实的新令牌，不改换认证协议。

跨标签页等待上限为刷新请求的 30 秒超时，若没有新会话则按失败处理。当前本地测试验证协调逻辑，未作真实浏览器多标签页端到端验收。
