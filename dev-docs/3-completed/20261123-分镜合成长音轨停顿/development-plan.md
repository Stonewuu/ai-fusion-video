# 分镜合成长音轨停顿修复

状态：代码修改与验证已完成，尚未发布。

## 问题与范围

当前分镜规范化使用 `apad -shortest`。在缓存后端镜像的 FFmpeg 8.0.1 中，4 秒画面加 25 秒音轨会生成 15.189 秒片段，后续镜头因此延迟约 11.189 秒。

修复分镜合成的片段时间范围与拼接边界，覆盖长音轨、短音轨、无音轨、不同帧率及缺少视频流时长的容器。

## 实现安排

1. 保留 `MediaFacts.durationMs` 表示整个媒体文件时长的约定，媒体检测增加明确读取视频流时长的入口。
2. 将片段处理独立为 `ComposeClipNormalizer`：先编码统一帧率的画面，再读取生成的 MP4 视频流时长，以同一时长裁剪或补齐音轨。第二步直接复制画面，不重复编码。
3. `ComposeVideoProcessor` 继续负责输入快照、租约、持久化与拼接。拼接显式使用规范化画面的时长，不用音轨或容器总时长决定镜头切换。
4. 两次处理都使用现有进程执行器的取消、超时与文件大小限制；临时文件随当前执行清理。已保存的任务结果继续按既有恢复约定复用，旧成片需要新建合成任务才能重新处理。

## 验证

- 用 FFmpeg 处理合成素材，检查视频和音轨时长、相邻镜头帧时间戳及原声保留情况。
- 覆盖 MP4、WebM、不同帧率、可变帧率、音轨延后开始、短音轨和无音轨。
- 运行媒体任务集成测试，验证加密媒体读取、任务恢复、取消与结果写回。
- 在此前复现问题的 FFmpeg 8.0.1 环境运行修改后的处理代码。
