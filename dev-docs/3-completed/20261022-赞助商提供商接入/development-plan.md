# 赞助商提供商接入设计

日期：2026-10-22。当前阶段：实现及最终验收完成。

2026-10-23 后续调整：新建入口、赞助商快速配置及已有账号自动读取已按用户反馈简化；当前交互流程见[入口与品牌标识交付总结](../20261023-提供商入口与品牌标识/completion-summary.md)。以下保留初版架构设计与协议范围。

## 目标

将秘塔 AI、无限星河 AI 纳入融光现有提供商体系。用户通过选择平台、填写密钥、勾选模型完成配置；平台资料、模型发现、协议映射和赞助说明可复用到后续提供商。

## 现有结构与设计依据

- 原前端 `API_PROVIDER_PRESETS` 只负责填表。本次已将既有条目迁入后端提供商目录，并单独持久化平台身份。
- `ApiConfig` 保存接入与鉴权类型、地址、密钥及各能力默认协议；一个配置通过 `AiModel.apiConfigId` 关联多个模型。
- 模型可通过 `modelProtocol` 显式覆盖协议，通过 `capabilityPresetCode` 引用能力预设。实际请求协议由模型覆盖或配置默认值确定。
- 当前远程模型导入会对未识别类型使用用户选定的默认类型，不能直接作为赞助商自动配置的准确性保证。
- 本次范围已经用户明确为对话、图片、视频；赞助界面和说明只呈现这三类。

## 赞助商与现有提供商的关系

采用统一提供商目录，赞助关系作为提供商的可选展示资料。

目录中 `sponsored` 只控制赞助展示及排序；`quickSetup` 表达快速配置能力，驱动发现入口、参数预设和密钥表单。取消赞助展示不会关闭快速配置，也不会更换模型协议或放宽密钥要求。

| 概念 | 责任 | 示例 |
| --- | --- | --- |
| 提供商身份 | 确定向哪一家平台购买和调用服务 | 秘塔 AI、无限星河 AI、OpenAI |
| 赞助资料 | 标识赞助关系、展示介绍及获取密钥入口 | 赞助标识、平台名称、链接 |
| API 配置 | 保存某一账号或密钥的连接信息 | 秘塔 AI·主账号 |
| 模型 | 保存上游精确模型 ID、类型、能力及配置关联 | MiniMax-H3 |
| 请求协议 | 决定鉴权后的接口路径、请求及响应格式 | OpenAI 文本协议、MiniMax 视频协议 |

关系：提供商定义 → 多份 API 配置 → 各自的多个模型 → 模型指定的协议适配器。

同一模型可以同时经官方渠道和赞助平台接入，分别归属各自 API 配置。模型研发厂商与服务提供商分别展示，例如模型属于 MiniMax、调用渠道属于秘塔 AI。

赞助信息不参与运行时协议选择、权限判断和任务状态流转。停止展示赞助关系不会删除用户配置或改变已有调用链。

## 数据与复用边界

1. 将现有前端提供商预设收敛为后端维护的提供商目录，前端从统一接口取得展示及配置资料，避免两边分别维护能力名单。
2. 提供商定义包含稳定 ID、名称、品牌标识、文档地址、获取密钥链接、赞助标识、连接预设、模型发现方式及经核对的模型映射。
3. `ApiConfig` 增加可空的 `providerId`，记录选择的平台身份；原有 `platform` 继续表达接入与鉴权类型，不混入商业平台名称。
4. 现有模型及 API 配置继续使用现有表。未绑定提供商目录的配置属于自定义配置，不根据名称或域名自动认领为赞助商。
5. 模型映射独立于赞助资料，记录精确上游 ID、模型类型、实际协议、能力预设及适用限制。不能因为 ID 与官方相同就继承官方所有能力。
6. 新增赞助商若完全兼容已有协议，主要增加目录与模型映射；只有真实接口差异才增加薄适配器，共用请求、任务查询、错误处理及媒体处理能力。
7. 已核对远端正式版本 v1.2.0；当前开发版本为 1.3.0，新增迁移序号 37，包含平台身份及新配置请求幂等字段。使用独立 MySQL 验证升级，不修改用户原有数据库。

## 用户入口

沿用“设置 → AI 模型”的提供商与模型管理。在新增提供商入口中优先展示“赞助合作伙伴”，与其他提供商使用同一套选择和配置组件；自定义接入继续可用。

平台条目显示名称、赞助标识和经核对的能力标签。选择后进入快速配置，不让普通用户先理解协议名称、路径补全及能力 JSON。

已配置平台仍出现在现有 API 配置列表，支持编辑密钥、追加模型和停用。再次选择同一平台时可选择已有配置追加模型，也可明确创建另一份账号配置。

## 快速配置流程

### 第一步：选择平台

从平台目录填入地址、鉴权方式、路径规则和协议映射。未支持的能力不显示为可选项。配置名称提供可修改的初始值。

赞助商和常见平台的 API 地址在选择后直接写入输入框，不仅作为占位提示。秘塔默认 `https://metaso.cn/api/minimax`，无限星河默认 `https://infistar.cc`；其余固定地址也来自同一目录。万相 3.0 的地址依赖所属业务空间，明确提示填写该空间的地域地址，不构造无效的通用默认值。

### 第二步：填写密钥

主要展示 API Key 与“点击【平台名称】前往平台获取密钥”。快速配置的高级设置可调整地址，代理等连接参数可转入常规配置编辑；修改连接目标后必须重新读取候选模型。

获取密钥链接由统一目录的独立 `credentialUrl` 字段维护。当前明确配置平台官网入口，未来收到 AFF 地址后替换该字段即可，不在表单和卡片中散落链接，也不向用户显示空链接或“待配置”。

### 第三步：选择模型并完成

系统取得候选模型，按真实类型分组，自动确定精确代码、显示名称、协议、能力预设和参数范围。用户勾选所需模型，一次完成 API 配置与模型保存。后续可在同一配置下追加模型，无需重复输入密钥。

不默认批量导入全部模型，不擅自更换已有默认模型。可以提供明确的“设为该类型默认模型”选项。

## 模型发现与准确性

统一的候选模型生成流程支持两种明确的数据来源：

- 具有官方模型列表接口的平台：读取当前密钥实际返回的模型，再与已核实的协议/能力映射结合。
- 未提供模型列表接口、但文档明确列出模型的平台：使用版本化的内置目录，并通过明确的只读接口校验密钥。界面标明模型来自平台预设，不声称逐一验证了模型调用权限。

两者由平台定义明确选择；模型列表请求失败必须显示失败原因，不静默切换到内置列表并声称验证成功。

模型处理规则：

| 情况 | 处理 |
| --- | --- |
| 账号返回且类型、协议、能力已确认 | 可直接勾选添加 |
| 账号返回但信息不足 | 展示为需高级配置，不能自动归类为对话或套用猜测协议 |
| 已确认该平台不提供此类型 | 隐藏该类型入口 |
| 列表加载失败 | 展示错误和重试，不能显示为“没有模型” |
| 同一 API 配置中已存在的同代码模型 | 标记已添加；重复操作不重复创建 |
| 同代码经不同 API 配置接入 | 允许分别保存 |

分组可见性需要区分平台理论能力、当前账号可用模型与融光已经完成适配的能力；未核实不等于不支持。

## 两家平台的当前判断

### 秘塔 AI

公开模型目录确认 MiniMax-H3、Seedance 2.0 Mini、Seedance 2.0，本次仅显示视频类型。

API 弹窗的模型、场景、通道、语言示例、请求及响应说明已通过公开页面资源逐项采集。生成模式作为能力或参数表达；真实独立的模型 ID 才作为独立模型记录。再生成依赖原任务来源与平台额外授权，本次不将其伪装成普通模型选项。

秘塔使用独立的 `/api/minimax/v2` 入口，复用 MiniMax 的内容结构与任务结果解析，路径、开关和能力限制由秘塔适配器和预设维护。

官方资料：https://metaso.cn/minimax-h3

### 无限星河 AI

官方提供 `GET /v1/models`，返回当前 API Key 可用模型；文档说明模型能否使用某接口还取决于分组和模型广场当前接口类型。因此列表用于确认精确 ID 与账号可用范围，不能假定它一定返回完整能力元数据。

按每个模型实际支持的 Chat Completions、Responses、Messages、Gemini、Images、Videos 等接口绑定现有适配器。尤其不能把所有文本模型都当作同时支持 Chat Completions 与 Responses，也不能因视频入口叫 `/v1/videos` 就套用只支持 Sora 参数的实现。

本次模型候选只呈现对话、图片、视频，按当前密钥权限与平台明确声明的接口筛选。

模型广场标记为图片生成但仅声明对话格式接口的条目，不自动归入对话。当前图片链路支持 Images 接口；未完成对应图片输出协议适配的条目不进入快速配置候选，避免把接口格式误当成输出类型。

官方资料：

- https://doc.infistar.cc/api-overview
- https://doc.infistar.cc/api-reference/models
- https://doc.infistar.cc/api-compatibility-matrix
- https://doc.infistar.cc/api-reference/video-generation

## 保存与后续管理

无限星河已配置 11 个图片、14 个视频的平台专属预设，仍需与账号返回的模型 ID、接口权限相交才出现在可选列表中。视频预设仅保留网关能够表达的参数：已知模型时长、适用时的单张首帧；尺寸显示“平台默认”，比例为自适应，实际请求省略 size，不继承原厂首尾帧、多参考和专属开关。文生与图生的必需输入约束独立保留。

未配置完整参数范围的图片、视频候选提供“配置”入口，自动带入模型名称、精确代码、类型和协议，由管理员补充能力；批量保存不接受未完成参数配置的候选。文本候选按明确的 Chat Completions、Responses、Messages 或 Gemini 接口选择协议，不按名称猜测。

秘塔 H3 的 Context IR 和优先通道使用独立能力标识及普通开关，默认关闭；切换开关只保存模型覆盖值，保留平台能力预设引用。

- 预览与模型发现阶段不产生正式模型；完成时由后端复核提供商、选择项、权限与重复记录。
- 外部请求在数据库事务之外执行；配置和所选模型的最终写入使用短事务，避免保存一半的状态。
- 重复提交必须避免重复创建。已有配置追加模型时保留用户修改过的名称、参数、并发及默认模型选择。
- 刷新远程列表只更新候选，不静默删除、替换或重写用户已保存的模型。
- 默认不带密钥的导出文件可以重新导入；缺少密钥的平台配置保存为停用状态并保留模型，补充密钥后才可启用，不把缺失密钥当作无需鉴权。
- 沿用现有管理权限、密钥保护和服务缓存失效规则。
- 连接验证和模型列表成功与实际生成成功分开表达，不为验证密钥自动发起收费生成任务。
