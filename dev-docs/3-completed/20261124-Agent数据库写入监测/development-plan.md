# Agent 数据库写入监测计划

比较智能助手和 pipeline 从提交一条消息到 agent 结束期间的数据库写入，确认执行引擎是否一致，并区分事件保存、心跳、消息保存和业务操作。

## 验证方法

- 使用当前工作区的后端构建，启动独立测试服务和临时 MySQL，复制本地数据库的表结构、模型及必要配置。
- 通过前端使用的 `/api/ai/pipeline/run` 接口提交请求，分别设置 `assistant`、`pipeline` 会话分类。对照组使用相同默认智能体、模型和消息。
- 对照短回复、长回复和一次只读工具调用，再执行一次 `script_full_parse` 业务 pipeline。
- 使用 MySQL Performance Schema 记录 SQL、影响行数和事务。以根运行终态事务提交为分界，分别统计结束前的写入和后续消息保存。
- 排除没有命中记录的后台维护，核对事件、消息记录与捕获的写入数量。

## 交付

记录每组的有效写入语句、UPDATE 语句、写事务、事件和心跳次数，说明相同执行引擎下次数变化的原因。测试脚本和原始输出保存在项目忽略的临时目录。
