# Agent 流式输出与对话还原完成说明

完成日期：2026-10-15。参考项目 `D:/develop/my/agenteam-package/agenteam`，AgentScope 从 2.0.0 升至该项目实际使用的 **2.0.4**。

## 原因与最终行为

原链路同时存在三类等待：提供商被强制设为非流式；`TrackedAgentChatModel` 收集整轮响应后再发送；日志写入、终态和审批恢复等待 Redis 通知完成。前两项直接造成长时间无字后整段出现，第三项在通知变慢时堆积后续内容。

现在七种模型协议都按增量传输，正文/思考直接通过；仅工具参数累计到流结束前校验。每轮模型请求仍只提交一次，真实用量照常记录，断线不自动重发。Google SDK 预读下一片的问题通过复用其格式转换、替换流读取边界解决；并行 OpenAI/Anthropic 工具片段按 index 保留身份。

沿用 50ms 事件合并和 MySQL 持久化序号，Redis 最新序号通知在独立有界批次发送，首次回放不等 Redis 握手。SSE（服务端持续推送连接）加入 15 秒心跳、防代理缓冲响应头，并取消 Servlet 默认连接超时。完整历史、接续与终态使用同一日志依据。

前端逐行解析 SSE，支持 CRLF 和中文 UTF-8 跨分片；未收到完整终态不判完成。只有成功应用的事件推进游标，处理失败不会永久跳过事件。刷新、切回、断线期间完成都会补全历史，迟到历史请求不能覆盖更新的实时内容；明确业务拒绝与提交结果不确定分开处理。

## 执行限制与保留范围

- 主/子 agent 默认 `run-timeout: 0s`、`max-iters: 0`，应用不设总执行时间和业务步数上限。SDK 边界表示、网络健康超时等见 `technical-debt.md`。
- 子任务等待不再受平台总期限或 SDK 默认五分钟工具超时截断，取消与所有权租约继续有效。子任务仅累计返回正文，不复制全部事件历史，保留空格/换行。
- 保留现有 `AiAgentDefinition`、`SubAgentToolDef`、工具 schema、白名单和注册方式，没有引入沙盒/命令/文件操作工具。
- 2.0.4 原生外部等待事件替代旧版手工补发逻辑，关闭额外 SDK 本地对话副本；无数据库迁移。
