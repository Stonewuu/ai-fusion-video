# 实测边界与问题

## 实测发现与后续处理

- 分集并行编写时，创建分集与写入其他分集场次都会推进分镜容器版本，导致部分分集创建反复收到 VERSION_CONFLICT。应明确不同分集的并发写入边界，避免把重复查询和重试交给模型消耗额度。
- 无限星河模型有时将 DSML 工具标记作为普通回复输出，运行记录显示完成但没有对应写入；第 13 集为空、第 14 集部分保存体现了这一风险。不能解析普通回复后直接补执行工具，应以持久化场次覆盖校验任务结果，并核查供应商工具调用协议。
- 陆阳受伤变体第一次请求带有画风图和原角色图；供应商拒绝后，智能体重试移除了两张参考图，虽生成并保存成功，但失去了角色一致性的输入约束。本次未认定角色一致性通过。后续已增加服务端首次参考图与媒体版本校验，并禁止审核拒绝后自动降级；再按用户要求完成同日“陆阳参考图复验”，任务 137 保留两张参考图并自动保存到子资产 86，版本更新为 2。
- 资产提示词原先以 itemType=initial 识别基础形象，而本项目基础子资产使用 character、scene、prop，变体使用 damaged 等值。上述修复已同步两层智能体提示词的基础形象识别，持久化数据未改动。
- 清空分镜集合的工具卡片仍显示 manage_storyboard_children 英文名称，尚待统一前端工具名称展示。

## 验证限制与保留数据

- 原 24 集重建没有全部完成。用户调整为保留 16 集场次齐全的分镜，其他部分进度保持原样；没有把部分分集计作完整成功。
- 图片验收覆盖智能体执行、生成状态、版本化写回、引用关系与页面加载，未逐个验证所有分镜引用的创作语义，也未对全部图片进行美术一致性评审。
- 工作台曾生成的 7 张候选图未绑定、未计入智能体验收，未擅自删除这些媒体。
- Chrome 旧标签曾出现控制超时和连接失效，后续新建 Chrome 标签可正常访问和操作。本次没有修改浏览器代理、权限或原生通信配置。
- 原始备份、截图、日志和查询结果保存在项目根目录 .local/verification，不加入 Git；开发文档只记录范围、结果和遗留问题。
