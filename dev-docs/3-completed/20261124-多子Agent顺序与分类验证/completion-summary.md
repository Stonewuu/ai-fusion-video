## 三轮验证

使用同一助手对话，父 agent 类型为 `script_full_parse`，分别并行委派三个 `episode_scene_writer`。第一轮解析三个独立分集，后两轮只读复核已经保存的内容。三轮均调用拓元 DeepSeek，没有使用模拟模型。

| 场景 | 结果 |
| --- | --- |
| 三子任务并发，断开流读取后续读 | 508 条事件，序号完整递增；三个子任务共同运行的时间为 37.181 秒，确认是并行执行 |
| 关闭 Chrome 页面，离线期间完成，再打开 | 页面在 18:02:46 关闭，运行在 18:02:57 完成；重开恢复两轮历史，共 6 个子任务分组；该轮重读 467 条事件 |
| 三个子任务执行中关闭 Chrome 页面，再打开 | 18:05:08.415 关闭，18:05:09.849 新开页面；自动恢复同一对话，已有历史和当前运行共 9 个子任务分组；后续内容继续到达，最终完成；该轮重读 546 条事件 |

三个测试都是读取连接中断或关闭页面，没有调用取消接口。数据库中相关运行的 `cancel_requested_at` 均为空，三次主动发起对应三个父运行，没有因重开页面增加父运行。

三轮合计 1521 条流式事件。将每轮事件分别送入对话、运行通知的消息处理逻辑，并与数据库历史转换结果比较：父工具分组顺序一致，子节点类型、顺序及文本一致，工具参数与结果归属正确。每轮均为三个独立分组，没有按相同 agent 名称合并。整个对话返回 245 条展示消息，其中用户输入 3 条、助手消息 70 条、工具消息 172 条；消息顺序号唯一且有序。

## 修复的问题

关页后重新读取历史时，接口原先把子运行的初始输入也按 `user` 消息返回。前端据此拆成多个用户轮次，父工具开始记录与结束记录被分开，出现重复子任务卡片和已完成任务仍显示运行中的情况。

现在历史查询根据运行的父子关系排除子运行的内部输入，保留子运行回复和工具记录。数据库中的内部输入继续保留，供执行恢复使用；不通过删除数据或前端猜测文本来修正分类。已经产生的历史数据同样按这个规则读取。

补充了集成断言：父对话只出现一条用户输入，子任务的助手回复保留，数据库仍存在子任务输入。新增前端回归覆盖三个同名子 agent 交错输出、完成顺序不同、子任务内工具编号相同及重复事件重读。
